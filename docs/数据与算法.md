# 数据与算法约定

给要改这个文件的人看的。这里记的是**已经定下来的规矩**，改之前先读完，
否则很容易踩到「看着对、音乐上不成立」的坑。

---

## 一、音高与拼写

- 音高一律用 **MIDI 音符号**参与计算。C4 = 60，A4 = 69。
- 音名拼写另有一套：升号与降号两套名字（`SHARP` / `FLAT`），由顶栏和卡片的开关决定当前用哪套。
  **拼写只影响显示，不影响任何计算** —— 计算永远在 MIDI 层面做。
- 调号决定「哪些音该拼成升号、哪些该拼成降号」，不要用「一律升号」糊过去。
- **和弦构成音的音级名不能直接查音级表** —— 走 `chordToneDeg(iv, 半音数, rootAsR)`。
  音级表是**音阶口径**的，一个半音数只配一个名字；而和弦里同一个半音数在不同和弦里
  担任的功能不一样，叫错了整个和弦的性质就没了（音名那套 `spellChord` 必须说同一件事）。
  判名只看两件事：**三音（`3` / `4` 半音）在不在**、**纯五度（`7` 半音）在不在**。
  - `8` 半音：增三 / 增大七 / 属七升五（五音位空着）→ `#5`；属七降十三（五音还在）→ `b13`。
  - `9` 半音：减七 `[0,3,6,9]` 的七音 → `bb7`；十三和弦 → `13`；六和弦族 → `6`。
    `Cdim7 = C · Eb · Gb · Bbb` —— 写成 `A` 就变成了一个带六度的和弦。
  - `2` 半音：三音在位（add9 / 九和弦族）→ `9`；挂二 sus2 没有三音 → `2`。
  - `5` / `6` 半音：三音在位时是 `11` / `#11`，否则是 `4` / `b5`。
  - **刻意不变**：`10` 半音永远是 `b7`（小七 / 属七 / 半减七一个写法）、`11` 永远是 `7`、
    纯五度永远是 `5`、小三度永远是 `b3`。
  - 传进来的半音数**根本不属于这个和弦**时（斜杠和弦的转位低音会走到这里）按音阶口径回表，
    别硬塞一个和弦功能名给它。
  着色仍按半音数走：`#5` 与 `b6`、`9` 与 `2`、`13` 与 `6`、`bb7` 与 `6` 是同一个音高，
  共用同一个 `DEGCOLOR` 色位（见 `DEG_SEMI`）。

## 二、定弦数据

- 19 条定弦，每条含 `id / name / inst / mid`。
- 分族：`g6` 11 条、`g7` 6 条、`b4` 1 条、`b5` 1 条（第 64 轮补了 6 弦全降全音 `dstd`
  与 7 弦全降半音 `g7half`）。
- **`mid` 是音高数组，索引 0 = 第 6 弦（最粗的那根）**，索引 5 = 第 1 弦。
  标准定弦是 `[40, 45, 50, 55, 59, 64]`。
- `inst` 取值：`g6`（6 弦吉他）、`g7`（7 弦吉他）、`b4`（4 弦贝斯）、`b5`（5 弦贝斯）。
  弦数、指板宽度、声部数、可用指型都由它推导。
- **非标准音程的定弦**（DADGAD、Open G、Open D、全四度等），以及原书没给指型的和弦性质，
  一律走 `deriveFromSkeleton`。
- 这个函数做的是**全局分配**，不是「每根弦各自挑最近的一个音」：
  1. 骨架（大三和弦五型）的槽位先摊开，每个槽位 × 每个和弦音级，取**位移最小的那个八度**当候选；
  2. 穷举「槽位数 ^ (音级数 + 1)」种组合（下标 = 该弦不弹），选代价最小的那一组。
  代价 = 总位移 + 0.4 × 跨度 + 3.5 × 静音弦数 + **缺音惩罚**，
  缺音惩罚分档：**特征音 100 ≫ 根音 20 > 三音 14 > 五音 6**。
  「特征音」= 不在大三和弦音级 `{0, 4, 7}` 里的那些（六和弦的 6、九和弦的 2、小大七的 7…）。
- ⚠ **为什么不能各挑各的**：骨架槽位上原本全是 1 / 3 / 5，逐格取最近必然整排原地不动，
  和弦里多出来的音一个都进不了图 —— 选「大六和弦」会画出一张和大三和弦逐格一模一样的图。
  这是第 28 轮修掉的真 bug（1320 张卡片里 60 张漏音），别再退回去。
- 分档惩罚的必要性：D 型只有 4 根弦的槽位，五音的九和弦（9 / m9 / maj9）本来就塞不下一个音，
  必须让它舍五音，而不是舍根音或三音（丢根音 = 这个型认不出是哪个型，丢三音 = 分不出大 / 小调）。
- 这会出现「多个型起品相同」的现象，是**既有设计**，不是 bug。
- 特殊定弦必须带 `mr`（marker）字段，且 **`mr.kind` 必填** —— 渲染读它来决定贴什么标签，
  缺了会被贴上错误的标签。

## 三、音阶体系：母音阶与子音阶

- 共 **82** 条音阶 / 琶音，分 **9** 大体系：
  自然大调 / 和声小调 / 旋律小调 / 和声大调 / 双和声小调 / 五声·布鲁斯 / 对称音阶 / 异域·Bebop / 琶音·和弦。
- 每条音阶有 `parent` 字段：
  - `parent` 为空 = **母音阶**
  - `parent` 指向母音阶 = **子音阶（调式）**
- **调式必须挂在各自的母音阶下、按调式级数排序**，不能平铺。这是这个工具和「一张音阶表」的核心区别。
- 非琶音音阶共 **59** 条（82 − 23 条琶音），这 59 条才有调式色彩档案。

### 听辨题库

- 按 **8 组母音阶体系**分组：勾选一个体系 = 「母音阶 + 它的全部子音阶」一起进题库。
- **干扰项必须剔掉音级结构相同的音阶**，否则题目无解（音程结构一模一样，光靠听觉不可能分）。
- 揭晓时报的是**体系名**，不是母音阶名。

### 调式色彩档案

- 每条音阶算一个「亮度」指标（音级质心），映射到光谱上的一档。
- 相邻音阶之间算色彩差异，给出「最接近 / 最远离」的音阶。
- 文案里不许出现具体书名、作者名、曲名、乐队名，也不许出现书名号 —— 来源改用品类描述
  （「一本 2-1-2 琶音专书」「一套三卷本把位指型全书」这种）。

## 四、把位与指型

### 把位是纵向的

**把位不是「沿琴颈横向截一段」，而是「从某根弦的某一品出发、逐弦向上铺开的一整条音型」。**
这是整个指型系统的地基，别用横向切片的思路去理解。

### 10 种指型系统

| id | 名称 | 跨弦音数 | 标准定弦下的块数 |
|---|---|---|---|
| `off` | 不分区 | — | 1（整条） |
| `3nps` | 一弦三音 | `3-3-3-3-3-3`（七弦定弦自动补成 7 项，见下） | 7 |
| `4nps` | 一弦四音 | `4-4-4-4-4-4`（七弦定弦自动补成 7 项，见下） | 5 |
| `pentwide` | 宽指型（本把位 7 品窗全取 · 一弦 3–4 音） | 一个 7 品把位窗里、每根弦上的**全部音阶音**（见下） | 5 / 6 |
| `313` | 3-1-3 跨弦 | `3-1-3-1-4` | 6 弦 14 |
| `212` | 2-1-2 琶音 两八度 | `2-1-2-1-2-1` | 28（4 弦贝斯 14、5 弦贝斯 21、7 弦 35） |
| `212b` | 2-1-2 基本型 | 3 弦 5 音 | 28 |
| `2nps` | 一弦二音（五声型） | `2-2-2-2-2-2` | 7 |
| `caged` | CAGED 五型色块 | — | 5（探索页）／**10**（指板练习：整条琴颈的**全部落位**，见下） |
| `box` | 把位窗 | 每 3 品一窗 | — |

**`pentwide` 与 `4nps` 互斥**：判据是「**音阶属于「五声 / 布鲁斯」族（`g === 'pent'`）**」——
这一族共 **12 条**（大调 / 小调 / 属五声、埃及音阶、平调子 / 阴旋法 / 云井调、五声调式 3 / 4 型，
以及布鲁斯 / 大调布鲁斯 / 小调六声），它们的 `4nps` 都铺不出来，那一档整个换成 `pentwide`；
其余音阶一律是 `4nps`。详见后面「宽指型：整个「五声 / 布鲁斯」族的 4NPS 替换」一节。

跨弦音数（`seq`）只决定「**每根弦取几个音**」；「这些音落在琴颈的哪一档」由下面那条
统一的选音规则现算 —— **两件事是分开的**，这是读懂这套系统最关键的一点。

**3-1-3 的要点**：跨弦音数是 `3-1-3-1-4` —— 最低弦 3 音，之后三根弦依次 1 / 3 / 1，
**最高弦 4 音**，5 弦共 12 音。最高弦比别的弦**多取一个音**，它最高的两个音同时落在
下一个把位的音集合里 —— 多这一个音就是为了**换把咬合**。弦数不够 5 根时（例如 4 弦贝斯）
按 `3-1-3-1` 截断，不套用最高弦规则。

**2-1-2 的要点**：

- 跨弦 `2-1-2-1-2-1`，最多 6 弦 9 音；只占 3 弦 5 音的那一小块叫**基本型**。
- 起始弦可以是第 6 / 5 / 4 / 3 弦；弦数不够时**自然截断**。
- **块内取音是三度叠置的琶音，不是连续的音阶音** —— 最常见的误解就在这。

### 换弦选音规则：7 品窗 + 「1 音弦」落中指 / 无名指

#### 为什么要重写

旧做法把跨弦音数按**标准定弦的弦间音程**定死，再靠 `skip` / `topSkip` / `preTopSkip`
一组手工参数去「错位」，让形状落在合适的品格上。这有两个毛病：

1. **开放调弦下不成立** —— 弦间音程不再是纯四度，手工参数没了依据。实测经典一弦三音
   在 DAEAC#E + 大调五声下，一整块要横跨 **17 品**。
2. **五声 / 稀疏音阶下指针单调漂移** —— 每换一根弦都在音阶指针上做加减，误差层层累积。
   实测旧规则在五声下：3-1-3 中位窗宽 **15 品**（最大 21）、一弦三音中位 **17 品**（最大 23）、
   一弦四音中位 **17 品**（最大 22）。

两条都不是「一个把位」该有的宽度。现在换成一条**对任何定弦、任何音阶都成立**的规则。

#### 规则（三步）

1. **窗**：整条指型横向限定在一个 **7 品窗** `[f0 − d, f0 − d + 6]` 内；`f0` = 锚点品
   （起始弦上的一个音阶音），也通常就是窗底。必要时窗可向左让 `d ≤ 4` 品 ——
   3-1-3 最高弦那条「4 个连续音阶音」最坏要跨 7 品，让窗左退几品才落得回 7 品窗内。
   `d` 对**豁免档也照扫**（豁免只免右端）：链式跑句会整体向左漂，把 `d` 锁成 0
   会让五声族被逼成跳进、一弦四音在五声下整块铺不出来。
2. **每根弦的起音**，按质量从高到低试三档：
   - **① 接续** —— 上一根弦走完，指针停在该弦末音的**下一个音阶音**上，下一弦就接这个音。
     多音弦（逐弦上行的跑句）与琶音弦（2-1-2 那一族，音是三度叠置的和弦音）**音是固定的**。
   - **② 跳进** —— 链上那个音落不进窗内时（定弦音程跳变太大，接续在物理上不可能，
     例如 Drop D / DADGAD 的第 6→5 弦差 7 个半音），取**高于它的第一个**窗内音阶音：
     跑句出现一次跳进，但绝不重复、绝不倒退。
   - **③ 回退**（只在 7 品窗这一档开）—— 前两档都铺不出来时，才允许起音落回窗底。
     这一档允许出现同音高重复，**只为把整条压进 7 品窗**。
   - **取音数为 1 的弦**（3-1-3 的两个「1」、2-1-2 的「1」）→ 优先落 **+1 / +2 品**
     （= 中指 / 无名指）；窗内没有这两个品位就退到最省力的那个 —— 宁可食指按住已有的品位，
     也不让手往右去够小指的位。
3. **取音**：自起音向上逐取连续音阶音（2-1-2 沿用三度叠置）；只要有一个音越出窗，
   该 (窗宽, 让位) 组合作废。7 品窗铺不下时窗宽逐品放宽（硬上界 11 品），
   低把位不会画出半条指型。

**⚠️ 循环顺序是「窗宽在外、质量在内」**：只要 7 品窗内铺得出来就一定要 7 品（哪怕只能靠
③ 的跳进 / 回退），7 品铺不下才逐品放宽，**放宽之后不再牺牲质量**（只用 ①②）。
这一条是第 38 轮定下来的：用户点名的目标是 7 品（第 39 轮由 6 品放宽），而质量只能让位于它。

#### 为什么必须有「接续」

第 36–37 轮曾把这条改成「每根弦各自贴窗左、换弦不递推」，理由是「不累积误差」。实测这是
**错的**：丢掉的不是误差，是**音链**。一弦三音的一条把位本该是「从低到高一条连续跑句」，
每弦独立贴窗左会让相邻弦取到同一个音高（重复音），2-1-2 的琶音音被换成别的音，一弦二音丢音。
量化结果（`p38chain.js`，判据 C1 跨弦上行 / C2 块内无重复音）：

| 指型 | 第 35 轮（链式） | 第 37 轮（丢接续） | 现在 |
|---|---|---|---|
| 212 琶音 | 100% / 100% | 56.1% / 60.0% | 97.4% / 98.0% |
| 212 基本型 | 100% / 100% | 81.8% / 82.4% | 99.2% / 99.2% |
| 2NPS | 100% / 100% | 66.3% / 66.3% | **100% / 100%** |
| 3-1-3 | 100% / 100% | 61.4% / 61.4% | 91.9% / 91.9% |
| 一弦三音 | 100% / 100% | **11.4% / 11.4%** | 76.4% / 76.4% |
| 一弦四音 | 100% / 100% | **0% / 0%** | **100% / 100%** |

（覆盖 17 定弦 × 4 音阶 × 6 指型，从渲染出的 SVG 反推 midi，期望值来自探针手写的乐理表。）

**剩下的缺口不是接续没生效，而是接续与 7 品窗在音程不规则的调弦里互斥**：一条一弦三音跑句
覆盖 17 个音阶音 ≈ 28 个半音，六根弦只跨 24 个半音 → 连续跑句必然要爬 5 品，加上弦内
2–3 品就是 **8 品**。Open D / DADGAD / FACGCE 这类弦间音程不是纯四度的定弦里，两者只能二选一。
按上面的循环顺序，**7 品优先**：这类卡走 ③ 回退，形状仍落在 7 品内，代价是跑句出现一次
重叠（`C2` 掉到 76.4%）。第 35 轮（用户认可的基线）在同样位置上给出的是 8–9 品窗。

#### 两条豁免

| 豁免对象 | 原因 | 实测窗宽 |
|---|---|---|
| `4nps`（每弦 4 音） | 一条弦就要跑满半个把位，7 品窗装不下 | 8–24 品 |
| **五声族音阶**（`g === 'pent'`，全族 12 条） | 每步 2–3 半音，一条 3 音跑句就要 4–7 品 | 4–13 品 |

豁免档同样**不启用 ③ 回退**（它本来就不判 7 品，没有达标压力，不该拿音的正确性去换）：
实测若在豁免档开 ③，一弦四音的无重复率会从 100% 掉到 45%。

一弦四音在**五声族**下会**整块铺不出来**（0 块）—— 每弦 4 音 × 6 弦 = 24 个音要走
4 个八度半 ≈ 55 个半音，而弦只跨 24 个 → 需要爬 31 品，24 品的琴颈放不下。这不是回归：
第 35 轮同样为 0 块。

**（第 41 轮起这条豁免对五声族逐步不适用 —— 那类音阶的 `4NPS` 档位换成了「宽指型
（第 46 轮定稿为「本把位 7 品窗全取」，见后）」：第 44 轮覆盖 9 条 5 音五声、
第 45 轮覆盖 3 条 6 音布鲁斯族，全族 12 条已换完。
下面这段推导保留作原理说明 —— 它解释了为什么这一族的 4NPS 铺不出来。）**

#### 七弦定弦：3NPS / 4NPS 铺满 1–7 弦（第 40 轮）

`seq` 里 3NPS / 4NPS 的骨架只写 **6 项**。七弦定弦有 7 根弦，于是骨架会**平移出两组**把位：
「第 7 弦起」（占 2–7 弦）与「第 6 弦起」（占 1–6 弦）—— 同一张图重复印两遍，各自少一根弦。

现在这两条指型带 `spanAll` 标记：骨架**按弦数补长**（重复最后一项，等价于「每弦 3 音 / 4 音 × N 弦」），
`minStr` 随之 = N，起始弦只剩一个 → **只出一组 1–7 弦组**。

- 作用范围只有 3NPS / 4NPS。3-1-3 / 2-1-2 的占弦数是**定义的一部分**（5 弦 12 音 / 6 弦 9 音），
  2NPS 与 2-1-2 基本型同理 —— 它们七弦上仍会滑出两组，这是有意的。
- 弦数比骨架**短**时（4 / 5 弦贝斯）不走这条路，仍是自然截断。
- 代价：每弦音数不变而弦数变多 → 跑句更长。七弦 4NPS 的窗宽从 16–17 品涨到 **17–19 品**
  （它本来就是豁免档）；七弦 3NPS 的中位窗宽仍是 **6 品**，非豁免档**全部 ≤7 品**。
- ⚠️ **`g7cs`（C#F#BEG#C#C#）上 4NPS 一块都铺不出来**：这个定弦 7 根弦只跨 2 个八度、
  最上面两根同音，而 7 弦宽的 4NPS 要 28 个音 ≈ 4 个八度，24 品琴颈放不下（该定弦的 3NPS
  在五声族下同样归零）。统一前的卡片是靠在 6 根弦上铺出来的，不是 1–7 弦组的解。
- 探针 `p40g7.js`：5 个七弦定弦 × 全部音阶 × {3NPS, 4NPS}，逐块断言

规则定弦 ＋ 5 音音阶上的**结果**。

窗取在哪儿只有一条规则：

> 窗 = `[f0 − d, f0 − d + 6]`（宽恒 **7 品**，`f0` = 起始弦上的锚点品）。
> `d` 取**最小的、让每一根弦都至少有 3 个音阶音**的值，上界 `DMAX = 4`。

- `d` 从 0 往大试，`lo < 0` 或 `hi > 24` 直接跳掉，**先命中先留** —— 于是天然偏好靠左的窗，
  也就是尽量把锚点品包在窗里。
- `d ≤ DMAX` 内做不到「每弦 ≥3 音」时**不丢整块**：取「完整弦数最多、其次窗内音数最多」
  的那一个窗（同分留 `d` 小的）。这是**尽力而为**，不是规则的一部分。
- 连「每根弦都有音」都做不到（`holes > 0`）→ 这一块作废。

**为什么是这条**：锚点数 = 音阶音数，所以 5 音音阶每定弦 **5 块**、6 音布鲁斯族 **6 块**，
与母音阶的把位一一对应。5 音音阶在 7 品窗内的自然形态**本来就是每弦正好 3 个**
（7 个半音必然容下 3 个相邻音阶音），所以它**看起来**像一弦三音 ——
但它比 `2nps`（= 五个盒子）横向铺得更开，练的是「把五声连成一条」而不是「记五个形状」。
6 音的布鲁斯族一弦 3–4 个（7 个半音里塞得下 4 个相邻音阶音）。
每弦 4 音（`4NPS`）才是那条在 24 品内铺不出来的路。

#### Bebop 三兄弟：母音阶骨架 + 把位内点缀经过音（第 43 轮）

大比博普 / 多利亚比博普 / 属比博普都比各自的母音阶多**恰好一颗经过音**，共 **8 个音**
（`1-2-3-4-5-#5-6-7` / `1-2-b3-3-4-5-6-b7` / `1-2-3-4-5-6-b7-7`）。
音数是 8 这件事本身就是例外 —— 全库其余音阶都是七个音。

**不能按这 8 个音重新排指型。** 那样会同时丢掉两样东西：母音阶的 **7 个把位**
（8 个音独立铺出来会变成 8 个）与母音阶的**手型**（图上认不出是哪一档）。
实测旧写法还多出一个假象：在 **7 弦 C# 定弦**（`C#F#BEG#C#C#`，末两根同音、只跨两个八度）上，
4NPS 对**任何七声音阶都铺不出来**，按 8 个音独立排却「铺」出了 5 块。

**定稿规则 —— 两步：**

1. **骨架照母音阶铺。** `SCALES` 里三条 bebop 条目带一个 `bp` 字段
   （`bebop_major → ionian`、`bebop_dorian → dorian`、`bebop_dom → mixolydian`），
   `bebopOrn(sc)` 据它拆出「多出来的那个音」`ex` 与「它在本音阶里的下方邻音」`lower`：

   | 音阶 | `bp`（母音阶） | `ex` 经过音 | `lower` 下方邻音 | 品差 |
   |---|---|---|---|---|
   | `bebop_dom` | `mixolydian` | `11`（7） | `10`（b7） | 1 |
   | `bebop_major` | `ionian` | `8`（b6） | `7`（5） | 1 |
   | `bebop_dorian` | `dorian` | `4`（3） | `3`（b3） | 1 |

   铺块时音级集合 `setLay` 换成**母音阶**的、锚点数量 `nAnch` 也按母音阶的 7 个算 ——
   于是 **bebop 的块数与母音阶逐组相等**，7 个把位与手型原样保住。
   `adv` / `layIn` / `pickW` 都加了可选的音级集合参数（默认仍是本音阶自己），
   所以**非 bebop 音阶的渲染路径一个字都没变**。
2. **经过音点缀进本把位。** `addOrnament(cells, win)` 扫本块：每遇到一颗 `lower` 音，
   就在**同一根弦**上把 `ex` 插到它后面（品差恒为 1 品），结果按品号排进该弦。
   一块里有几颗 `lower` 就点几次 —— 跨两三个八度的 3NPS / 4NPS 通常点 2–3 次，
   正好对应「每个八度一颗经过音」。
   **越出本把位品窗的不点**（7 品窗是硬指标）；**骨架里根本没有 `lower` 的块也不点**。

**为什么判据是「紧跟在下方邻音之后」、而不是「把经过音塞进窗内任何能放的位置」：**
三条音阶的 `lower` 恰好都是**和弦音**（属比博普的 `b7`、大比博普的 `5`、多利亚比博普的 `b3`），
所以经过音永远贴着和弦音上沿，2-1-2 那种**三度叠置**的琶音指型也接得住；
脱离下邻音的孤零零一颗经过音在图上没有意义，也会把品窗撑破。

**⚠️ 两套坐标必须换算。** `bebopOrn()` 返回的是**相对主音的半音数**，
而音位比较用的 `pcOf(mid + f)` 是**绝对音级**。不换算只在主音 C 上碰巧对，
其余 11 个主音会照「相对半音数恰好等于某个绝对音级」去找下邻音，
把经过音点到别的音上（第一次跑探针报出 41273 条 FAIL）。现在 `buildBlocks` 里一律先过
`((S.root + x) % 12 + 12) % 12` 换算成绝对音级再比。

### CAGED 五型是「位置窗」

**不是和弦手型。** 定义：

- 每个型锚在某根弦的根音上：`A → 第 5 弦`、`G → 第 3 弦`、`E → 第 6 弦`、`D → 第 4 弦`、`C → 第 2 弦`。
- 窗口 = `[根音品 − 1, 根音品 + 3]`。
- 相对位置量：`C = r5 − 3`、`A = r5`、`G = r6 − 3`、`E = r6`、`D = r4`
  （其中 `r6 = r5 + 5`、`r4 = r5 + 7`）。
- 相邻型的间距恒为 **3, 2, 3, 2, 2** 品（全为正、和为 12）→ 升序排列的结果必然是该循环次序的某个**旋转**。
- **只跟主音走、与音阶无关**；贝斯族没有 CAGED，返回 `null` 退回骨架指型。
- 窗位是**绝对品位**，不许按显示范围裁剪。
- **显示次序 = 按「实际最低音品」升序重排**（`CAGED_ORDER` 记的是循环次序 `C→A→G→E→D`，
  显示一律走 `cagedOrderByPos()`）。所以**最左边恒为品位最低的那个型**。
- 起始点取各调最顺手的开放把位：C 调从 C 型、G 调从 G 型、A 调从 A 型、D 调从 D 型。

#### 「练哪些位置」要枚举整条琴颈的全部落位（第 70 轮）

上面这一组五窗是**教学图**口径（一张图印一遍就够）。但「指板练习 → 选择位置」要能点到
**每一个具体把位** —— 同一个型在低把位与高把位各有一份，只给一组就点不到另一份。
所以 `cagedScaleWindows()` 多一个可选参数 `all`：

- **不传**（探索页色块图 / 分屏 / 旧存档）：仍是上面那组五窗，输出**逐字节不变**。
- **传真值**：把 `k ∈ {…, −24, −12, 0, +12, +24}` 每个八度各一组都枚举出来，
  再按**窗底升序**排。排序不是装饰 —— `buildBlocks` 的「本位区 = 本窗起 … 下一窗起前 1 品」
  靠这个次序才成立，五型因此仍**不重叠地铺满琴颈**。
- 窗位是**绝对品位**，`hi` 可以越过 24 品（实测 C 调 D 型是 `21–25`），
  取音与绘制时各自按 0–24 裁（见 `buildBlocks` / `neckSVG`）。

| # | 判据 | 说明 |

## 五、声部连接代价（最核心的一条）

### 为什么不能按半音算

同一个音高在指板上有**多个落点**：`2 弦 5 品 → 1 弦空弦` 音高一动不动，手却要从 5 品挪回 0 品；
反过来 `6 弦 5 品 → 5 弦 7 品` 音高差 7 个半音，手只挪 2 品。

按半音算会挑出「A7 在第 12 品、E7 在第 7 品」这种**音高差很小、实际要跳半个指板**的连接，
而真正只挪 2 品的那组反被淘汰。

### 为什么也不能只按品位算

只按 `Σ|Δ品|` 会让**声部音高乱跳**（实测「各声部音高移动量」中位从 5.4 半音飙到 17.0），
失去「声部连接」的意义 —— 弹出来不像连接，像随机抓音。

### 定稿公式

```js
const VC_STRK = 0.35;   // 跨一根弦（纯四度 5 个半音）折算 1.75 品
const VC_HAND = 1.0;    // 整只手位中心挪 1 品记 1 品代价
const VC_PEN  = 3.4;    // 声部数不齐时，多出 / 少掉一个声部的罚分

/* 一个声部从 a 挪到 b 的代价，单位「品」 */
function vcFingerMove(a, b){
  if (a.f === 0 && b.f === 0) return 0;        // 两根空弦：左手不用动
  const df = b.f - a.f, dm = b.midi - a.midi;
  return Math.abs(df) + VC_STRK * Math.abs(dm - df);
}
```

即：

```
代价 = Σ[ |Δ品| + 0.35 × |Δ半音 − Δ品| ]        ← 逐声部
     + 1.0 × |vcHand(a) − vcHand(b)|            ← 整只手位中心位移
     + 3.4 × 声部数不齐的个数
```

**三项缺一不可**，各自的理由：

| 项 | 缺了会怎样 |
|---|---|
| `|Δ品|` | 会按音高挑出跳半个指板的按法 |
| `0.35 × |Δ半音 − Δ品|` | 手钉死了但声部音高乱跳，音乐上不成立 |
| `1.0 × 手位位移` | 会挑出「每根手指都只挪一点、整只手左右横跳」的按法。**诊断信号：受限的分档方案反而优于「全局最优」** |

**关于空弦那条 `return 0`**：它必须保留。空弦不用左手按，这条是对的。
删掉它「各声部音高移动量」会略好（7.57 → 6.08 半音），但整体解会被推离空弦 ——
E 调 12 小节布鲁斯的默认按法从 0–4 品一路挤到 7–11 品，对练习者明显更差。
**聚合层面的手位由 `VC_HAND` 管，不是靠删这条。**

### 两个计算路径必须同值

为了速度，`vcMove`（DP 用）对 4v4 / 5v5 走**预置排列表**的快路径。
**给代价函数加任何项，都必须同时加到快路径上**，否则 DP 优化的是旧目标、界面报的是新目标，
静默分叉。回归时有专门断言：`vcMove(a, b) === vcPair(a, b).cost`。

### 参数

- `vcPair` / `vcMove` 接收的是 **voicing 对象**（要读 `.f` 与 `.midi`），不是 midi 数组。
  改签名时**必须全局替换所有调用点**，漏一个会静默算出 `undefined`。
- `vcSolve` 的 `add()` 累计 `handSum / semiSum / fingerSum` 供界面展示。
- `VC_BANDS = [低, 中, 高]` 三档把位区，用于生成「低把位 / 中把位 / 高把位」的受限方案。

### 实测（100 首伴奏带 / 1000 个相邻和弦对）

| 指标 | 值 |
|---|---|
| 手位移动 中位 | **0.5 品** |
| 手位移动 均值 | **0.39 品** |
| 手位移动 90 分位 | **1.0 品** |
| 手位移动 最大 | **2.0 品** |
| 偏离该对候选最小值 ≥ 4 品的 | **0** |

## 六、k-best DP 与剪枝

- `vcSolve` 用 k-best 动态规划：每个和弦保留若干候选，`VC_KEEP = 6`。
- 剪枝是否剪掉了最优解，**用一份独立实现的 k-best DP 对照证明**：
  把 K 拉成 6 / 16 / 48 跑同一批数据，断言「K=6 比 K=48 差的有 0 首」。
  本项目 25 首逐首差异全为 0 → `VC_KEEP = 6` 安全，不必为了保险调大（调大直接拖慢整页）。
- 其它参数：`VC_PERWIN = 8`（每个把位窗内保留的候选数）、`VC_OUT = 3`（输出的方案数）。
- ⚠️ 这一章整章都**只服务模式一「声部连接最优」**。第 72 轮新增的模式二
  「最常见 / 最易按」**完全不进 DP** —— 它是逐和弦独立的另一条路，见「十四」。

## 七、玩点即兴的坐标系统一

同一屏里三处都在说「这个和弦弹在哪」：

1. 和弦卡的角标 `.vpos`
2. 素材表的「本方案把位」列

4. **坐标一致**：从渲染结果里把三处把位数字都抓出来，断言指板图的每一段都能在另两处找到。

10. **谱表配置化之后高音谱表必须逐字不变**（第 53 轮）：用**结构级**比较（取 `<g>` 内部内容
    逐字比），16 个用例覆盖四分 / 八分 / 二分 / 全音符 / 附点 / 三种休止符 / 上下加线 /
    临时记号 / 调号 4 升 5 降 / 3/4 拍 / 跨小节线临时记号 / 音名标注 / ✓✗ 标记 / 灰显 / 空谱 ——
    内容必须逐字相同，只允许画布的上下沿差一点点（yTop 11.300 → 11.267，yBot 不变）。
11. **贝斯视奏的音域窗**（第 53 轮）：加线条数**独立重算**，断言窗的两端恰好落在

    **反证**：把窗摘掉、品数放宽到 0–24，谱位立刻跑到 4 条加线 —— 证明这个窗真在起作用。
12. **谱位 → y 的换算必须带上当前谱表**（第 53 轮补丁 E）：符头 / 加线 / 附点三处的 `cy / y`

    ⚠️ 这条是**相对判据抓不到**的：漏传谱表参数时符头按高音谱表换算，
    而画布也跟着**同一个错值**一起撑大，两者自洽 —— 「墨迹在 viewBox 里」那条全绿，
    真正错的却是位置（低音谱表下整条走句低了一个八度 = 12 个谱位 = 6 个间距 = 66 y 单位）。
    所以**凡是「由 ds 算位置」的地方都要有一条绝对落点断言**，别只验「在画布内」。

## 九、点音反查（「和弦查询」/「音阶查询」）

第 47 轮新增的两个栏目走的是**反方向**：不选音阶再看指板，而是在指板上点音，反推和弦或音阶。

### 共用的点音指板

两页共用一块可点的指板（`pickSVG()`，**不复用**探索页的 `neckSVG()` ——
那个函数整条挂在全局音阶 / 根音 / 指型上，点音反查用不到那些，硬接进来反而更容易坏）。
两条规矩：

- **匹配只看音高类。** 同一个音在高音弦、低音弦各点一次，只当一个音算（`pickPcs()` 去重）。
- **低音 = 已选里 midi 最低的那个位置**（`pickLow()`），不是「先点的那个」。
  斜线和弦 `X/Y` 的 `Y` 就是它；图上套一圈**虚线环**标出来（第 48 轮起低音不抢颜色，
  改用形状编码 —— 原先这里写的是「实心圆」，已勘误）。

### 只有两个音时：先给音程，再给两音和弦（第 50 轮）

和弦匹配的门槛按音高类算是 3 个（`cqResults()` 里的 `need`），点满 2 个音原本只剩一句
「还差 1 个音」—— 可这两个音已经能说清一件事：它们是什么音程。现在 `pcs.length === 2`
走**另一条路**（`cqTwoHTML(pcs)`），出两条**各自明确写出**的结果：

| 条目 | 写什么 |
|---|---|
| **音程关系** | 低音 → 高音 的两个音名、音程名（含国际缩写）、半音数，再加一条**反向读数** |
| **和弦** | 是两音和弦就写名字（原位 / 转位）；不是就写「不适用」并说明为什么没有 |

**方向按实际音高定**，不按「先点哪个」：

```js
const bass = pickLow();                    // 已选里 midi 最低的那个位置
const lo = bass.pc, hi = pcs.filter(x => x !== lo)[0];
const iv = (((hi - lo) % 12) + 12) % 12;   // 从低音往上数的半音数
```

这与第 47 轮定下的「低音决定斜线记法」是同一条口径 —— 同一对音、换个摆法，
不该出现两个互相打架的读数。

**音程表 `CQ_IV12`（12 项）**，下标就是半音数：0 纯一度 / 1 小二度 / 2 大二度 / 3 小三度 /
4 大三度 / 5 纯四度 / 6 三全音 / 7 纯五度 / 8 小六度 / 9 大六度 / 10 小七度 / 11 大七度。

⚠️ **和 `INTERVALS` 是两张表，不要合并。** `INTERVALS` 的成员就是「音程听辨」模式的
选项清单（改它会连带改那个功能），这里只需要文字名，而且必须补齐 `0` 与 `11` 两端。

**反向读数**（从高音往低音数）不用另写一张表：

```js
const B = CQ_IV12[(12 - iv) % 12];   // 0 与 11 两端都落回表内
```

**两音和弦 `CQ_TWO_POW = [5, 7]`。** 构成音天生只有两个的和弦，通用标记里只有一个 ——
五和弦（强力和弦 `X5`，根音 ＋ 纯五度）。两种摆法都算同一个和弦：

| `iv` | 摆法 | 写法 |
|---|---|---|
| `7`（纯五度） | 低音就是根音 | 原位 `X5` |
| `5`（纯四度） | 低音是五度、根音在上面那颗 | 转位 `X5/Y` |

其余 9 个音程（二度 / 三度 / 三全音 / 六度 / 七度）**不硬安名字**，改成写清楚
「为什么没有」—— 这正是「和弦」这一条的意义：是就写名字，不是就说清楚不是。
（第 72 轮按用户要求把界面上的标识由「特殊和弦」改成「和弦」，只是文案。）

这条逻辑**只在恰好 2 个音时触发**：3 个音起走原来的三种匹配方式；
1 个音时仍提示还差几个音，只多一句「点满 2 个音可以先看这两颗音的音程关系」。

### 和弦引擎：三类读法 + 一个先验

粗匹配枚举 **12 个候选根音 × 46 条和弦性质**（`QUERY_QUALS`，比「即兴查询表」的 `CHORD_QUALS`
宽一档：补齐六和弦、九 / 十一 / 十三、变化属，以及各种**缺音形态**），每条性质分三种读法：

| 读法 | 含义 | 惩罚项 |
|---|---|---|
| `exact` | 点出的音与该和弦构成音**完全一致** | 只有性质常见度 |
| `extra` | 和弦对得上，另外多按了几颗（延伸音 / 附加音） | `2.2 × 多出音数` |
| `miss` | 点出的音都在和弦里，和弦还差几个音没按 | `3.0 × 缺音数` |

排序键：

```
pen = 2.2·extra + 3.0·miss + 0.55·w
    + (根音没点出 ? 5 : 0) + (低音不是根音 ? 1.5 : 0)
```

⚠️ `miss` 读法**只在根音被点出时才认真考虑** —— 否则任何三个音都能被说成某个七和弦的碎片，
结果会泛滥得没法看。

### 「可能性」先验是从本机语料数出来的

`degPrior()` 把教材进行集（`BOOK`，100 条）里每颗和弦根音按「相对主音的半音数」计数、归一化。

⚠️ **只数 `BOOK`，不数 `PROGS`。** 经典进行那 10 条几乎全落在大调体系内，
偏移 7 出现 8 次、偏移 0 只有 10 次 —— 一旦加权，V 会反压过 I（实测 `7:203 > 0:178`），
「I 最靠前」这条就没了。只用教材这一份语料，实测（偏移:次数）

```
7:171   0:138   5:119   9:115   2:89   4:86   11:8
```

即 **V > I > IV > vi > ii > iii > vii°**。两个主力 V 与 I 咬得很紧，这也是教科书语料与文献
都认的结论（古典语料里 I 常略高于 V，流行语料里反过来；本机这份是后者）。

调内和弦（`cqDiatonic`）的「可能性」= 多出来的和弦音越少越靠前 + 该级越常见越靠前。

### 调内和弦的体系：只留五个七声体系（第 49 轮）

```js
const CQ_DIA_GROUPS = ['major', 'harm', 'mel', 'harmaj', 'dblmin'];
```

自然大调 / 和声小调 / 旋律小调 / 和声大调 / 双和声小调 —— 它们都是七声音阶体系，
每一级都能三度叠置出一个「这个调下的和弦」。其余家族（五声与布鲁斯、对称音阶、
异域与 Bebop、琶音）要么音数不是七、要么根本谈不上「调内各级和弦」，不进这个下拉。

⚠️ **体系与母音阶是两个状态，不能混。** `CQ.pgrp` 是体系（组 id，如 `major`），
`CQ.psc` 是母音阶（音阶 id，如 `ionian`）。第 49 轮之前只有一个 `psc`，却被当成组 id
去查 `scalesOf()` —— 而 `scalesOf` 过滤的是 `s.g`（组 id）。查询恒空 → 回落 `major`
→ 把刚选的体系冲掉 → `psc` 不在 `major` 组里又被打回 `ionian`。
**净效果：除「自然大调体系」外，任何体系都选不上。** 现在由 `cqDiaNorm()` 保证两者始终自洽：

```js
function cqDiaNorm(){
  let sc = scaleById(CQ.psc);
  if (CQ_DIA_GROUPS.indexOf(sc.g) < 0) sc = scaleById('ionian');
  if (CQ_DIA_GROUPS.indexOf(CQ.pgrp) < 0 || CQ.pgrp !== sc.g) CQ.pgrp = sc.g;
  CQ.psc = sc.id;
  return sc;
}
```

两个下拉的选项由同一个 `cqGroupOptsHTML()` 生成 —— 原先 `fillPickCtrls()` 里铺的是
**全部 9 个组**，只因 `cqRender()` 紧接着会调 `fillCqScaleSel()` 覆盖掉才没露馅。

### 双和声小调族：非常规三度叠置不许硬说成大三和弦

这条音阶有增二度、连着两个半音，三度叠置会给出 `1 3 b5`（`0·4·6`）、`1 2 #4`（`0·2·6`）
这类**教材上不存在的三音组**。原先把 `TRIAD_TYPE` 查不到的情况默认成 `maj`，
于是罗马数字把它们写成大写级数（`II`），等于说「这里是个大三和弦」—— 说谎。
改为查不到时**小写 + 问号**（`ii?`），并在行内直接写出它的音程（`D(0·4·6)`）。
实测双和声小调族七条音阶共 21 处，全部落到这条兜底上。

### 斜线和弦：两个必须写对的判据

1. **低音不是根音 → 写 `X/Y`**（`chordSym(root, q, bassPc)`）。
2. **「低音自己当根音」的那套名字，要放开音级约束另算一遍。**
   音级一旦标出，根音就被钉死了（每颗已知音级都在反推同一个根音 —— 其实只剩一颗候选根音），
   在结果列表里找 `root === bassPc` 永远找不到。
   ⚠️ 曾经写成 `c.root === bassPc && c.root !== c.bassPc` —— 后半段恒为假，整段从不显示。

### 调内细匹配标的是「和弦内的位置」，不是「音阶的级数」

母音阶一旦选定，「哪颗音是音阶的几级」就已经定死了 —— 拿它当判据等于把母音阶复述一遍，
**永远为真，细匹配就退化成粗匹配**。所以 `CQ_DIA_OPTS` 标的是
**这颗音是该和弦的第几个音**（1 / 3 / 5 / 7 / 9 音），判据：

```js
want.forEach(w => { if (w.d >= sz || cps[w.d] !== w.pc) okWant = false; });
```

标「调外音」（值 `-2`）时直接空手而归，页面说明原因。

⚠️ **判「某颗音没标音级」必须用 `typeof v === 'number' && v >= 0`**，
不能写 `v >= 0` —— 后者分不清「没设置（`undefined`）」和「明确选了 0 = 根音」。

### 对不上任何和弦时：三音组五族

那套体系（去掉七声音阶的根音 → 剩 6 音 → 拆成两个三音组）把每个三音组归入五族：
**三和弦 / 四度叠置 / 音簇 / 七和弦缺五音 / 七和弦缺三音**，每族恰好 4 个成员
（C 伊奥尼亚去掉根音后 6 个音取三 = 20 颗 = 5 族 × 4）。
`trichordReads()` 按转位读数判族（可多条），`trichordFam1()` 取次序最前的那个族，
次序 = 三度叠置 → 四度叠置 → 音簇 → 七和弦缺音。这个次序能在那 20 颗上**逐条复现**书里的划分。

⚠️ 音簇的判据曾经写成 `iv[2] <= 4 && iv[0] >= 1`，而 `iv` 是**从最低音算起**排好序的，
`iv[0]` 按构造恒为 0 → **音簇这一族永远判不出来**（4 颗音簇全被错划进「七和弦缺三音」）。
现在用「两个相邻音程都 ≥ 1 且严格递增」，等价于「三个互不相同的音、跨度 ≤ 4」。

三音组不再往下面拆，就没有歧义了；六个音正好拆成两个三音组，按十种配对判能不能配
（三和弦 / 四度叠置 / 音簇**不互相配**，每族都能配 7th no 5 与 7th no 3）。

### 音阶引擎：判据是「同时装得下」，不是「逐对音程」

`sqSearch(pcs, tonic)` 在 **82 条音阶 × 12 个主音 = 984 条读法**里找
「点出的音高类集合 ⊆ 该音阶在那一主音下的音高类集合」。

⚠️ 这个判据比直觉里的「点出音之间的每个音程都能在音阶里找到」**更严**，
而后者是**必要非充分**的：`{C, Eb, G}` 的成对音程 {3, 4, 7} 在 C 大调里都存在，
但 `Eb` 根本不在 C 大调里 —— 逐对音程判据会把它误收进来。页面底注里写明了用的是哪一条。

**一条结果 = 一组音高类，不是一个音阶名。** 同一组音往往有好几个名字：

- 七声音阶的同一组音有 7 个读法（C 伊奥尼亚 = D 多利亚 = …），
- 五声音阶有 5 个（C 大调五声 = A 小调五声 = …），
- 对称音阶更极端（全音阶转 2 / 4 / 6 / 8 / 10 个半音都还是它自己）。

所以结果按集合聚合，把**同一组音的全部读法并列**出来、每个都能一键当主音进细匹配 ——
「七声音阶只能给出母音阶组」说的就是这件事。细匹配把主音限死之后，被排除掉的那半
会以「同一组音另有读法」再列一次（也能点，点了就换主音）。

⚠️ **「同音异名」和「旋转移调对称」是两件事**：五声 `{0,2,4,7,9}` 转 3 个半音是
`{3,5,7,10,0}`，跟原集合**并不相等** —— 它只是能换个主音换个名字。
`sqSymmetry()` 只判后者（转 d 个半音后集合仍是它自己），用来标出「连主音都分不出来」的对称音阶：
全音阶 `[2,4,6,8,10]`、减音阶 `[3,6,9]`、增音阶 `[4,8]`、半音阶 `[1..11]`。

排序：先按「还差几个音」分层，同层按体系常见度（自然大调 > 五声布鲁斯 > 和声小调 >
旋律小调 > 和声大调 > 双和声小调 > 异域 / Bebop > 对称 > 琶音），再按组内是不是母音阶、
再按音数，最后才看「低音是不是某个读法的主音」（只是微调，翻不过体系那一层）。

### 点音反查的交互约定（第 48 轮）

**结果必须跟着点击走。** `pickRepaint()` 现在同时重画指板、已选列表**和结果区**；
以前它只画前两者，于是点完音结果区纹丝不动，非得再碰一下模式按钮 / 换个下拉 / 切一次页
才出结果。两页各算一遍（12×46 与 984 条读法）都是毫秒级，换来的是「点了就有」。

**「位置数」和「音高类数」是两回事。** 同一个音在四根弦上各点一次，是 4 个位置、1 个音；
匹配只看音高类。所以：

- 门槛按**音高类**算（和弦 3 个、音阶 5 个），提示里把两个数都写出来；
- 上限按**位置数**算（`PICK_MAX_POS = 24`，软上限，超了给提示而不是静默丢弃）。
  ⚠️ 旧的写法是「位置数到 12 就把最早点的那个音 `shift()` 掉」—— 位置数根本不该卡
  （6 个音铺在 4 根弦上就 12 个位置了），而且静默丢音会让人以为工具算错了。

**已选的音按音高类上色。** 色相按**五度圈**排：`pc → ((pc × 7) mod 12) × 30°`，
一共 12 个色相。好处是五度圈上相邻的两个音色相相差 30°，半音邻居（E/F、B/C）也分得开 ——
旧的「低音红 / 其余蓝」两色方案下，点三四个音就是一片同色，看不出哪几颗是不同的音。
**低音不再抢颜色**，改用外面一圈**虚线环**标（形状编码）。明度按色相的感知亮度分档
（黄绿系 34%、蓝系 46%），让 12 个色块都压得住白字；一套色、两套主题共用。

**落在显示范围外的位置**仍然参与匹配（判据只看音高类，与显示范围无关），
但会在已选列表里带「范围外」角标、并在计数里报出来 —— 看不见却算数，必须说明白。

| --- | --- |

### 谱表配置（第 53 轮）

渲染层原本把「高音谱表」硬编码在每一处；第 53 轮把它抽成两张配置表，渲染器只认表：

```js
const STAFF_TREBLE = { key:'treble', cn:'高音谱表',
  clef:ST_CLEF, clefW:ST_CLEF_W, clefUp:ST_CLEF_UP, clefDn:ST_CLEF_DN,
  anchor:32, top:38, mid:34, bot:30,                    /* G4 / F5 B4 E4 */
  sharpDs:[38, 35, 39, 36, 33, 37], flatDs:[34, 37, 33, 36, 32, 35] };
const STAFF_BASS = { key:'bass', cn:'低音谱表',
  clef:ST_BCLEF, clefW:ST_BCLEF_W, clefUp:ST_BCLEF_UP, clefDn:ST_BCLEF_DN,
  anchor:24, top:26, mid:22, bot:18,                    /* F3 / A3 D3 G2 */
  sharpDs:[24, 21, 25, 22, 19, 23], flatDs:[20, 23, 19, 22, 18, 21] };
const STAFFS = { treble:STAFF_TREBLE, bass:STAFF_BASS };
```

两种谱表**只有这三组数不同**：谱号与它的锚线、五线的谱位、调号里各记号落在哪个谱位。
音符 / 符干 / 符尾 / 休止符 / 小节线的画法完全一样。

`anchor` 是谱号字形原点的对准线（高音谱号 = G 线，低音谱号 = F 线）。
画布的上下沿不再写死，而是按谱表自己算：

```js
topOf    = min(stY(st.top, st), stY(st.anchor, st) + st.clefUp * ST_SP)
bottomOf = max(stY(st.bot, st), stY(st.anchor, st) + st.clefDn * ST_SP)
```

⚠️ 两张谱表的**五线画在同一批 y 上**（顶线都在 `ST_TOP = 30`）—— 这是刻意的：
题板高度不随谱表变，换谱表只换谱号与「哪个谱位算哪个音」。所以同一段像素
在高音谱表上读作 E4–F5、在低音谱表上读作 G2–A3。

### 声部配置（第 53 轮）

出题内核收一个「声部」= 谱表 + 记谱八度 + 音域窗，三处不同全在配置里，内核不写 `if`：

```js
const SIGHT_VOICE = {
  guitar:{ key:'guitar', cn:'吉他视奏', staff:STAFF_TREBLE, oct:12, win:null,  ref:60 },
  bass:  { key:'bass',   cn:'贝斯视奏', staff:STAFF_BASS,   oct:12, win:[12,32], ref:40 }
};
function sightVoice(){ return isBassInst() ? SIGHT_VOICE.bass : SIGHT_VOICE.guitar; }
function sightMake(len, v){ … }                          /* 内核 */
function sightAsk(len){ return sightMake(len, SIGHT_VOICE.guitar); }   /* 吉他 */
function bassSightAsk(len){ return sightMake(len, SIGHT_VOICE.bass); } /* 贝斯 */
```

`ref` 是「起音尽量靠主音或五度」那一步拿哪个八度来比「近」—— 贝斯取 40（低把位中部），
吉他取 60（中音区）。

**音域窗按谱位（不是按实际音高）来限** —— 要控制的量是「谱面会拖出几条加线」，
而同一段实际音高落在两张谱表上的加线数不一样。窗的两端：
谱位 12 = 谱面 A1 → 实际 A0（`midi 21`）；谱位 32 = 谱面 G4 → 实际 G3（`midi 55`，G 弦 12 品）。
真正的下限由定弦自己决定（4 弦空弦 E1、5 弦空弦 B0）。退化成「范围里能点到的音」时
**仍然不许出窗** —— 谱面出界比少一个音严重。

### 谱面坐标系

单位是一个「谱表间距」`ST_SP = 11`（px）。谱位 `ds = 字母序号 + 7 × 八度`（C0 = 0 … B0 = 6，C1 = 7 …）。

高音谱表五条线 **E4 = 30、G4 = 32、B4 = 34、D5 = 36、F5 = 38** —— 全偶，奇数就是「间」。
低音谱表五条线 **G2 = 18、B2 = 20、D3 = 22、F3 = 24、A3 = 26**。加线也落在偶数上。

```
stY(ds, st) = ST_TOP + (st.top - ds) * (ST_SP / 2)       ST_TOP = 30，st 缺省高音谱表
```

⚠️ 谱位必须落在**偶数**上才是「线」，奇数就是「间」；附点、加线、符干方向都靠这个前提，
换谱表时别把这个性质弄丢。

加线条数：`ds > st.top ? floor((ds - st.top) / 2) : ds < st.bot ? floor((st.bot - ds) / 2) : 0`。
紧贴底线 / 顶线的那个「间」不需要加线（低音谱表谱位 17 是 0 条，16 才 1 条）。

⚠️ **记谱八度是调用方的事**：吉他 / 贝斯都按各自的惯例把实发音高换算成谱面音高，
渲染器拿到 `ds` 就当它已经写好了 —— 渲染层不认识「吉他 / 贝斯」，只认 `ds / acc / dur / rest`。

### 调号

`ST_KEY` 把「主音音高类 → 调号升降数」定死；**F# / Gb 那一格两种写法都试**，取临时记号更少的那个。
判定「这套音阶配不配这个调」用代价函数：`代价 = 音阶外音数 + 0.5 × 范围外音数 + 0.02 × |调号| + 0.001 × 次序`，
**代价 < 3 才给调号**，否则一律写临时记号（五声 / 布鲁斯多数落在这里）。

调号里各记号的谱位**挂在谱表配置下**（`STAFF_TREBLE.sharpDs` / `STAFF_BASS.sharpDs` …）——
第 53 轮以前是顶层的 `ST_SHARP_DS = [38, 35, 39, 36, 33, 37]` / `ST_FLAT_DS = [34, 37, 33, 36, 32, 35]`，
谱表配置化之后那两份副本**删掉了，只留一份**（两份同样的数迟早改一处漏一处）。
累积字母序 `ST_SHARP_L = [3, 0, 4, 1, 5, 2, 6]` / `ST_FLAT_L = [6, 2, 5, 1, 4, 0, 3]`
是**与谱表无关**的（次序由五度圈决定），仍在顶层。

两张谱表的调号谱位可以独立验：**`ds % 7` 必须等于该记号字母的序号**（C=0 D=1 … B=6）。
升号链 F C G D A E = `3,0,4,1,5,2`；降号链 B E A D G C = `6,2,5,1,4,0`。
六个升号 + 六个降号合起来正好铺满 **8 个连续谱位**：高音谱表 `32–39`（第 2 线到顶线上方的间），
低音谱表 `18–25`（底线到顶线下方的间）—— 真谱怎么排就怎么排。

**临时记号只在「和默认值不一样」时才写**：`stImplied(sig, L)` 给出这个字母在本调号下本来该升还是该降，
再看本小节里这个字母前面出现过什么（`accMem`），跨小节线一律清空。
⚠️ 这个判据只许有这一处实现，别再内联写回循环里。

### 字形

高音谱号 / 四分休止符 / 升号 / 降号来自 Wikimedia Commons（**公有领域**），由脚本归一化成
「高度 = 1、左边缘 = x0、竖直中心 = y0」的 path 内联进文件 —— 本机没有音乐字体，不能靠 `font-family`。
还原号是手写矩形拼的。**低音谱号**（F 谱号）同样来自 Wikimedia Commons（公有领域）。

宽度常量 `ST_CLEF_W / ST_QREST_W / ST_SHARP_W / ST_FLAT_W / ST_NAT_W` 是归一化时量出来的，别手改；
谱号另有 `ST_CLEF_UP / ST_CLEF_DN`（高音）与 `ST_BCLEF_W / ST_BCLEF_UP / ST_BCLEF_DN`（低音）。

⚠️ **画完一个记号必须把它自己的纵向墨迹报给 `up()` / `dn()`**（`stAccSpan()`）——
`yTop` / `yBot` 在绘制过程中**只扩不收**，任何漏报的新元素都可能被 viewBox 裁掉。
高音加线 + 临时记号就是被这条咬到的（探针 S2 节抓到 4 例）。

#### 低音谱号的定标（第 53 轮）

低音谱号字形的素材**自带五线**（间距 590.5，第 4 线 y = 6968 = F 线）。把 path 按 `M` 拆成
3 个子路径：主体（1292 × 1907）＋ 上点（261 × 260）＋ 下点（261 × 261）。

定标依据是一条**标准里恒成立**的性质：**谱号那两个点的中心距 = 一个谱表间距**，
且两点中心的中点正好落在 F 线上。而素材里两点中心距只有 523.5（= 0.886 个间距）
→ 素材整体等比缩小到 0.886 倍，再按「F 线 = y0、左边缘 = x0」平移到原点。

自检（探针 S3 节从字形本身复算）：修正后两点中心距 = 1.000、两点中心的中点 = 0.000、
点直径 = 0.497（设计值 0.5）—— 都对上了。结果 `ST_BCLEF_W = 3.152`、
`ST_BCLEF_UP = -1.094`、`ST_BCLEF_DN = 2.549`（单位都是一个谱表间距）。

⚠️ 低音谱号是 **F 谱号**：字形原点对准 **F 线**（低音谱表第 4 线，`anchor: 24`），
不是五线的正中间。高音谱号同理，原点对准 **G 线**（`anchor: 32`）。

#### ⚠️ 所有 `stY(ds)` 都要带谱表参数（第 53 轮补丁 E）

`stY(ds, st)` 的 `st` 缺省 `STAFF_TREBLE`。谱表配置化那一轮，`stStaffSVG` 里
**符头中心 / 加线 / 附点**三处漏传了 `st` —— 低音谱表下这三样被按高音谱表换算，
而两张谱表**相差整整一个八度**（12 个谱位 = 6 个间距 = 66 个单位），
症状是**整条走句掉到谱表下方六格、还挂出一串多余的加线**。谱号 / 调号 / 五线 / 拍号 /
休止符 / 小节线当时都带了参数，所以只看这些会以为画对了。

三处现已修好：`stY(n.ds, st)`（符头中心，符干与符尾都跟着它）、`stY(d, st)`（加线）、
`stY(dds, st)`（附点）。判定办法：**两张谱表下同一句走句的符头 y 必须各自 = `stY(ds, 该谱表)`**，
差值恒为 66 —— 探针 S4 节就是按这个比绝对落点。

顺带把**拍号**也报给了 `up()` / `dn()`（数字高约 0.72 em、坐在基线上）：
高音谱表有谱号在上面兜着看不出来，低音谱表的谱号只向上伸 1.09 个间距，
不报就会让题板上沿贴着拍号走。

### 节奏槽位

一小节折合 `per = 拍号分子 × 2` 个八分音符单位。
`SIGHT_PAT` 是中途小节可用的节奏型（允许八分音符）；`SIGHT_PATE` 是收尾小节用的 ——
**不准出现八分**，因为剩余槽位要补成休止符，而八分休止符这一版没做。

### 出题（`sightMake(len, v)` + 两个出口）

内核收一个**声部** `v`（见上面的 `SIGHT_VOICE`）；吉他与贝斯共用走句、节奏槽位、拼写与调号，
三处不同（谱表 / 记谱八度 / 音域窗）全在声部配置里。两个出口就是两行：

```js
function sightAsk(len){ return sightMake(len, SIGHT_VOICE.guitar); }
function bassSightAsk(len){ return sightMake(len, SIGHT_VOICE.bass); }
```

- **池子 = 用户勾选的母音阶组**（复用「音阶听辨」的 `EAR_GROUPS` / `earPool()`，琶音不进池子）。
- 梯子 = 当前可点范围里**属于本题音阶**且**落在音域窗内**（按谱位判）的音高，升序排列。
- 走句 = 梯子上的随机游走：75% 级进 / 25% 跳进，走出 ±7 半音就掉头；
  起音尽量落在主音或五度，末音尽量回主音（拿 `v.ref` 那个八度比「近」）。
- 一小节一小节铺：每小节从 `SIGHT_PAT` / `SIGHT_PATE` 取一个节奏型，把音符填进槽位。
- `len` 从下拉读（夹在 3–12，默认 5）。**题目音允许重复**。
- 范围里点得到的音凑不满时置 `r.narrow`，题板上明写一句提示，不静默少音；
  贝斯题那句提示会多一句「（再算上低音谱表的常用音域）」。

**出题内部仍然用「实际发声音高」（midi）走句**，只在两处换算成谱面：判音域窗、算谱位与音名。
这样判定（卡八度，比 midi）与谱面互相独立，换谱表不会牵动判定。

### 拼写（谱面上写什么字母）

`pc` → 「字母 + 升降数」的写法不唯一（`pc = 6` 可以写 F#、也可以写 Gb）。两条规矩：

- `sightAlt(pc, flatPref)`：在 7 个字母里挑 **|升降数| 最小**的写法（> 2 不要），同分按调号偏好。
  ⚠️ 不许退回「找半音邻居的字母」那种写法 —— 对**自然音级**会两个 `indexOf` 都是 -1、
  落到兜底写成 C 本位（实测：C 布鲁斯的 G 被写成 C，谱面变成 C + 五个降号）。
- `sightWritten(midi, letters, octShift)` 再按**八度**定谱位，返回 `{ L, acc, oct, ds }`；
  `sightWName(midi, letters, octShift)` 给同一套写法的音名串（`F#4`）—— 谱下标注与作答行共用它。
  `sightMajorLetters()` 由调号反推「这个调里各字母的升降数」。

⚠️ **记谱八度必须由调用方显式传入**（`octShift` 就是 `SIGHT_VOICE.*.oct`）。
`octShift === undefined` 时有个兜底默认值，但那个默认值只是防手滑 ——
它掩盖不了真正的错：今天吉他 / 贝斯恰好都是 +12，靠兜底蒙对了；换个八度口径就露馅。
所以作答行、谱下标注、判音域窗这三处**全都显式传**。

⚠️ 音名显示的是**谱面音名**（记谱音高），所以贝斯题上写的是比实际发音高一个八度的名字 ——
这与谱面一致（用户看的是谱面，不是手在琴上按的音高数字）。

### 作答与判定

- 作答按**位置**有序记录 `{ s, f, pc, midi, nm }`，**不做集合去重** —— 题目音允许重复。
- 判定逐位比 **`midi`**：**卡八度**。同一个音高换个把位算对，点成别的八度算错。
- 全对 → 加分 + `finishRound()` 自动下一题；有错 → 谱面上那几颗标红叉 + 扣 6 分 + **停在本题**。
- 进度条走的是**作答数 / 题目长度**，不是完成题数。
- 提交后谱面上打 `✓` / `✗`（`n.ok`）；再点音时整批作废（`n.ok = null`）。

### 「同音高全亮」

`renderTrain()` 末尾调 `sightAfterRender()` —— 先重建题板 DOM，再打类。
`sightPaintSame()` 按 **`g.note[data-midi]`** 匹（不是 `data-pc`）—— 卡八度之后，
「同音高」指的是**同一个音高**，不是同一个音高类。
打 `.same` 类并把 `circle.nc` 的 `stroke` 写成该音高类的 `--pkN`（与「和弦查询」同一套 12 色）、
`strokeWidth` 写成 `3.4`；原值缓存在 `dataset.oS` / `dataset.oW`，撤回或换题时还原。

⚠️ **不在共用的 `neckSVG()` 里加分支** —— 那是探索页 / 指型分屏 / 视听练习共用的渲染路径，
一动就波及全部页面。而且 `renderTrain()` 每次都重建 `innerHTML`，
`.same` 与 JS 写进去的 `stroke` 会一起消失，**不必反向清理**。

### 换定弦时怎么走（第 53 轮）

顶栏 `tuningSel` 的 onchange 里，在 `fillStringSel(); refreshAll();` 之后补一段：

```js
if (G.type === 'sight' && G.round && G.round.kind === 'sight'
    && G.round.voice !== (isBassInst() ? 'bass' : 'guitar')) newRound();
```

判据用**乐器族**（`isBassInst()`）而不是定弦 id —— 同一族内换定弦（4 弦 ↔ 5 弦、
各种开放定弦之间）保持当前题，跨族才换。不写这一段程序也不会崩，但会留下一道
「在新定弦上根本点不出来」的题 —— 那不是 bug，是折磨。

题目自己记得该画在哪张谱上：`G.round.staff` / `G.round.voice` 由出题结果带过来，
题板渲染时把 `r.staff` 直接传给 `stStaffSVG(…, { st: r.staff })` ——
**题板不查定弦，只认题目自己带的谱表**。（空题兜底那条分支也要带 `staff` / `voice`，
否则题板会拿到 `undefined` 回落到高音谱表。）

### 读谱辅助

- **▶ 试听题目**（`sightPlay()`）：按谱面音高依次放，`beat = 470 ms`；休止符只占时间不出声。
  定时器全进 `rawTimers`，换题 / 结束练习时统一清掉。
- **☐ 显示音名**（`S.sightNames`）：在谱下按 `_x` 对齐标 `F#4` 这样的音名。
  判定标记行**始终留位**，免得提交后整块跳一下。
- **两支视奏的默认都是「关」**（第 73 轮起对齐）：渲染层只在 `o.names` 为真时才画那一行，
  而题板把 `S.jdNames` / `S.sightNames` 原样传下去 —— 所以「默认关」就是 `sanitize()`
  里那一个布尔值，没有第二处开关。

### 谱面显示宽度

`ST_ZOOM = 1.35`：只作用于 **CSS 显示宽度**，`viewBox` 与所有内部坐标保持 1 倍 ——
窄窗口仍由 `max-width:100%` 兜住；全体同倍，音符大小跨题一致（不像「铺满宽度」那样短题巨大、长题很小）。

⚠️ `viewBox` / `width` / `height` 三个属性必须是**内容自己的尺寸**（1 倍），放大只写在 `style` 里；
否则探针那套「自己算坐标」的判据会跟着失真。

### 常量与 TDZ

`SIGHT_MIN / SIGHT_MAX / SIGHT_DEF` 定义在视听练习那一段，而 `S` 的字段归一化跑在更早的
`S` 初始化 IIFE 里 —— 那时这几个常量还在 TDZ 中。所以 `S.sightLen = num(S.sightLen, 5, 3, 12)`
里的上下限只能写**字面量**，改那几个常量时这几行要一起改。

## 十一、视奏练习 —— 简谱视奏（第 71 轮 · 第 72 轮拆出两套旋律小调记谱法）

上一节的**第二张脸**：同一套出题槽位、同一套作答判定，题目换成**首调数字谱**。

### 一句话口径

**五线谱写的是「哪个音」，简谱写的是「这条音阶里的第几个音」。** 所以简谱题必须额外交代一件事：
**「1」落在哪个绝对音高上**。题板左上角把它写出来（`1 = X`），右上角写这条子音阶的首调长相。

### 首调串 = 母音阶基串循环左移

五条体系的母音阶在 `GROUPS` / `SCALES` 里**本来就存在**，本块只补「首调串」这一层，
不新建任何音阶数据。`JD_SYS` 给每条体系一个**基串**（`[级数, 升降]` 的数组，按演奏顺序）：

**第 72 轮起 `JD_SYS` 的键是「体系实例 `id`」，不再是音阶组 `gid`** —— 旋律小调有两套首调记谱法，
同一个音阶组 `mel` 因此占**两行**（`mel_la` / `mel_do`），六条体系实例并列：

| 体系实例 `id` | 音阶组 `gid` | 面板标题 `cn` | 母音阶基串 |
| --- | --- | --- | --- |
| `major` | `major` | 自然大调体系 | `1 2 3 4 5 6 7` |
| `harm` | `harm` | 和声小调体系 | `6 7 1 2 3 4 #5` |
| `mel_la` | `mel` | 旋律小调体系 · 1 = la | `1 2 b3 4 5 6 7` |
| `mel_do` | `mel` | 旋律小调体系 · 1 = do | `6 7 1 2 3 #4 #5` |
| `harmaj` | `harmaj` | 和声大调体系 | `1 2 3 4 5 b6 7` |
| `dblmin` | `dblmin` | 双和声小调体系 | `6 7 1 #2 3 4 #5` |

⚠️ `id` 是**唯一键**，`gid` 只是「这条实例引用哪个音阶组」—— 两列并不总是相等。
`jdSysOf(k)` 先按 `id` 查、查不到再按 `gid` **回落该组的第一行**
（`jdSysOf('mel')` 恒得 `mel_la`，即第 71 轮的老口径）—— 新代码一律传 `id`，
回落那一支只是为了让老调用逐字节不变。
⚠️ 面板标题必须读 `JD_SYS` 的 `cn`，**不能回 `GROUPS` 查组名** —— `mel` 两行共用一个组，查组名分不开。
⚠️ 升降号用升还是降**由该题调号决定**（`keyFlats(jdFramePc(...))` → `o.flatPref`），
跟系统无关，所以这张表里不再列「拼写偏好」一栏。

```js
jdStrArr(sysId, m)  // 循环左移 m 位后的文本数组，如 ['6','7','1','2','3','4','#5']
jdStr(sysId, m)     // 拼成一串，如 '671234#5'
jdInfo(sc, sysId)   // → { sys, sysId, gid, cn, parent, m, strs }；不属这六条实例的一律 null
jdSysGroups()       // → JD_SYS.slice()（面板拿 id 与 cn 直接渲染）
jdGroupScales(id)   // 该体系实例下全部可选音阶（母音阶在前），恒 7 条
```
⚠️ 入参一律是**体系实例 `id`**，不是音阶组 `gid` —— 传 `gid` 只会拿到该组的第一行。

`jdInfo` 用 **`iv` 旋转反查**定 `m`（`jdModeIndex`），**不读** `SCALES` 的 `deg` / `parent` 字段 ——
大调调式那批的 `g` 是归一化时才改写的，元数据不保证齐。

⚠️ 还有一道**张冠李戴**的闸门：`sys.gid !== sc.g` 时直接返回 `null` ——
`mel_la` / `mel_do` 共用同 7 条音阶，「这条音阶不归这个体系」宁可判无解，也不许硬算。

### 组合键：`(体系实例, 音阶)` 才是选择集的唯一元素

`mel_la` 与 `mel_do` 共用同 7 条音阶 —— 只存音阶 id 根本分不开两套记谱法。所以选择集的元素是
**组合键** `jdKey(sysId, scId) = sysId + '|' + scId`（音阶 id 里不含 `|`，全表唯一）：

```js
jdKey('mel_la', 'mel_minor')   // → 'mel_la|mel_minor'
jdKeySys(k)                    // '|' 之前 = 体系实例 id
jdKeyScale(k)                  // '|' 之后 = 音阶 id
jdAllScaleIds()                // 全表 6 × 7 = 42 条组合键
```

组合键还有一层实用好处：读存档时**逐个键过一遍 `jdInfo`**，第 71 轮留下的裸音阶 id
会被整条滤掉，于是自动落回「六条体系实例全选」，不报错也不留半截状态。

⚠️ 简谱视奏只认这六条体系实例：五声 / 布鲁斯 / 对称 / 异域 / Bebop / **琶音**一律 `jdInfo → null`，
所以它们不会出现在简谱题库里（琶音本来就不设色彩档案，这里的口径是一致的）。
**六条体系实例 × 各 7 条 = 42 条。**

### 音高 ↔ 首调数字

```js
jdFramePc(sc, rootPc, sysId)            // 「1」的音高类
jdRef1(sc, rootPc, anchor, sysId)       // ≤ anchor 且音高类 == framePc 的那个绝对音高
jdNote(sc, rootPc, midi, ref1, sysId)   // → { txt:'#5', dot:-1..2, in:true|false }
```
⚠️ 三支都多了一个**可选尾参 `sysId`**（体系实例 id）。不传时按 `sc.g` 回落该组的第一行
（`mel` → `mel_la`），行为与第 71 轮**逐字节相同** —— 这是本项目一贯的零回归手法。

⚠️ **`jdFramePc` 的基准必须取 `inf.sys.base[inf.m]`，不是 `base[0]`** ——
本条音阶的主音坐在基串的**第 `m` 位**（`m` = 调式序号），子音阶的首调串整体被左移过了，
「1」对应的音程位也跟着移。取 `base[0]` 会让子音阶全体算错
（例：自然小调 A 会算出「1」= A，正确的应是「1」= C）。

`jdRef1` 的 `anchor` 取本题声部锚点（`sightVoice().ref`，通常 60 / 40）：
「1」的相对位置一定，同一段音高按不同的 1 去读会得到完全不同的数字 —— 所以
**「1 = X」必须和音阶、主音一起定死**，题板左上角写的就是它。

⚠️ **`1 = X` 读作「数字 1 记在 X 这个音上」，不读作「X 是主音」。** 同一个 A 旋律小调：
`1 = la` 写成 `12b34567`（小调本位），`1 = do` 写成 `67123#4#5`（大调本位，第 3 级记 `b3`）——
两种读法差一个三度框架，都对，所以两套都留。基串里的级数是**母音阶框架内的级数**，
不是「本条音阶自己从 1 起数」（若改成 do 基准，「自然小调 = `6712345`」这条立刻不成立）。

`jdNote` 的音阶外兜底（窄范围兜底题会用到）回落成「以 1 为基准」的通用级数表 `NUM`，
返回 `in:false`。

### 出题：复用 `sightMake`，只加一个可选尾参

```js
sightMake(len, v, { pool: 子音阶 id 数组, jd: true })
```

- `pool` 换掉题库（五线谱那边是 `earPool(S.sightGroups)`，简谱这边是 `S.jsSel` 展开的子音阶表）；
- `jd: true` 让每个音符多带 `it.jd = jdNote(...)`、题目对象多一个 `ref1`；
- **不传 `o` 时逐字节保持原行为**（零回归手法）。

⚠️ 音名口径不同：五线谱走 `sightWName(midi, ky.letters, v.oct)`（**谱面音名**，吉他 / 贝斯都高八度记谱），
简谱走 `nameOf(midi, S.flats) + 八度`（**实发音名**）。简谱没有谱表八度的概念。

### 题目对象同形 → 六处作答逻辑一个字都不用改

简谱题的 `G.round` 与五线谱题**同形**（`kind:'sight'`），只多 `jd: true` 与 `ref1` 两项。
于是 `trainClick / sightUndo / sightClear / sightPaintSame / sightSubmit / sightTipText`
**整条链路直接复用** —— 作答、撤回、清空、提交、同音高全亮、判定卡八度、计分与连击全都一样。

⚠️ 判「是不是简谱题」要**看真值**（`!!r.jd`），不能写 `r.jd === false`：
五线谱那条分支**从不写这个键**，值是 `undefined`。整条链路用的都是真值判断。

只有四处按题型分流：`newRound`（建题）、`sightBoxRender`（画题板）、`sightAfterRender`、`sightMake`。

### ⚠️ 作答牌子的音名口径：两条链各写各的（第 82 轮）

`trainClick` 里「作答牌子上写什么音名」按题型分流**一次**：

| 题型 | 牌子上写的是 | 函数 |
| --- | --- | --- |
| 五线谱视奏 | **记谱音高**（＝实发 + 声部 `oct`；吉他 / 贝斯都是 +12） | `sightWName(midi, r.letters, SIGHT_VOICE[r.voice].oct)` |
| 简谱视奏 | **实际发音** | `jdSndName(midi)` ＝ `nameOf(midi, S.flats) + (floor(midi / 12) − 1)` |

```js
nm: r.jd ? jdSndName(midi)
         : sightWName(midi, r.letters, (SIGHT_VOICE[r.voice] || SIGHT_VOICE.guitar).oct)
```

⚠️⚠️ **这两条口径不能混。** 第 71–81 轮，简谱那条沿着五线谱的写法走 `sightWName`，
于是牌子上写的音名比题目**整整高一个八度** —— 题目的简谱高低音点、谱下「显示音名」
（`it.name`）用的都是实发口径，只有牌子是记谱口径。用户照着牌子读谱，就会**整整低一个八度**
地点下去：5 个音全判错，而旧版 `jdScoreSVG` 一个标记都不画，屏幕上给不出任何线索
（`sightTipText` 那句「（谱面红叉）」当时是句空话）。

出题侧 `it.name` 一并改调 `jdSndName` —— 与旧写法**输出逐字节相同**（同一个表达式只是换了名字），
把「简谱题一律走实发口径」收拢到一个函数上，避免下一处再写反。

### 判定标记画在谱面上（第 82 轮）

`jdScoreSVG` 补两个标记（`stStaffSVG` 早就有，简谱这条一直缺）：

- `it.ok === true` → 数字**右上角**一个绿勾 `<text>✓</text>`；
- `it.ok === false` → 压在数字**右半边**的红叉（两条 `stroke-width:2.1` 的 `<line>`）——
  左半边数字仍可读，能看清错的到底是哪一个音；
- `it.ok === null`（还没提交）→ **一个都不画**，输出与第 81 轮逐字节相同。

`n.ok` 由 `sightSubmit` 逐位写（`x.midi === r.ask[i]`），由 `trainClick` / `sightUndo` /
`sightClear` 整批清成 `null` —— 与五线谱那条同一条链路，没有另开状态。

### 谱面：`jdScoreSVG`（与 `stStaffSVG` 并列的另一个渲染器）

纯字符串函数，无依赖，一列 = 一拍：

| `dur` | 画法 |
| --- | --- |
| 0.5 | 数字 + 下加一条下划线（八分） |
| 1 | 数字本身（四分） |
| 1.5 | 数字 + 附点（附点四分） |
| 2 | 数字 + 一条增时线「−」（二分） |
| 4 | 数字 + 三条增时线（全音符） |

⚠️ 附点只在「整数拍 ≥ 1 且余 0.5 拍」时成立：`dur 0.5` 是**八分音符**（下划线），
不是附点。少了 `nn >= 1` 这一半，八分音符会被画成「1·」并多出一个附点圆心。

其余：升降号是小一号的 `<tspan>`（`#5` / `b3`）、高低音点是数字上下方的小圆心、
休止符一律写 `0`、小节线由**累计拍数是否整除拍号**决定。
⚠️ 渲染层**不读全局常量** —— 调号拼写用升还是降由 `o.flatPref` 传，音阶 / 主音 / 锚点全靠 `o`。

### 表头排版：只扩不缩 + 按 room 裁名（第 71 轮修的 bug）

第一行要同时放左「`1 = X`」和右「音阶名 · 首调串」，两段都必须完整可读。三条规矩：

1. **版面宽 = `max(列宽, 表头所需宽)`，只扩不缩**（同 `psScoreHTML` 的思路）。
   表头所需宽 = `padL + jdTxtW(hd1) + 16 + JD_NAMIN + jdTxtW(hdT) + padR`。
2. **`JD_NAMIN = 64`** 是留给音阶名的**下限**。
   ⚠️ 少了它，「表头那一支」在短题面（3 列 = 138px）配短主音时会赢，
   于是 `room = (W - padL - padR) - jdTxtW(hd1) - 16 - jdTxtW(hdT)` 恰好算成 **0**，
   音阶名整段被换成光秃秃一个「…」。
3. **首调串永远完整**；宽度不够时只裁音阶名（补省略号）。

宽度是纯字符串函数，没有画布可量 —— 所以用「CJK 12.2px / 其余 6.6px」的**保守**估法

## 十二、指板练习：位置选择器与八档走句方向（第 64–68 轮）

### 位置的单位 = `(pid, bi)`

**一块 = 指型系统 `pid` 里的第 `bi` 块**，直接复用 `buildBlocks().list`，不另造坐标系。
于是「一块」天然等于：通用把位分支的一个把位 / CAGED 的一份落位（一个型在某一个把位，
第 70 轮起整条琴颈上共 **10** 份）/ 把位窗的一段三品窗。

- 位置空间实测（0–24 品）：**五声 / 布鲁斯族 81 处**，**六声族 94 处**，**七 / 八声族各 107 处**，
  都是 8 个系统 **19** 行（第 70 轮把 CAGED 从「1 行 5 处」扩成「5 行 10 处」：行 +4、处 +5；
  换成 0–12 品则依次 70 / 71 / 93 / 95）。
  五声族**没有 4NPS**、六七八声族**没有宽指型**（同一槽位互相顶替）。
- 目录走 `patternList()`，**不能遍历 `PATTERNS`** —— 后者会列出铺不出块的槽位。
  且**只列与当前品段相交**的位置。
- 真相源三个字段：`S.fpPosOn`（0 跟随 / 1 自定义）、`S.fpPos`（`'pid:bi'`，`|` 分隔，
  **书写序 = 点选序**）、`S.fpOrd`（0 品序 / 1 点选序）。三者都进 `sanitize()` 白名单；
  `fpSelList()` 另按**归一化键**去重，手改存档也兜得住。
- ⚠️ **过滤而非清空**：对不上的位置项**不写回 `S`**，只在这一帧滤掉；滤完全空时临时走「跟随指型」。
- `fpMergeBlocks(sel)` → `{list, of}`：idx 重编号、`color` 按新序号（相邻必不同色）、
  `label` 加指型短名、`win`/`zone` **置 `null`**（那是「把位分屏」专用字段，照抄会让
  `psScoreHTML` 误判），并新增 `fw`（本块实际用到的那一段品）。
- ⚠️ **`fpCellsOf` 必须反查 `b.of`**，不能照 `rows` 的 lo..hi 铺 —— `rows` 是每弦的**包络**，
  相邻把位大面积重叠，铺出来会多出别人的音。

### 换把区标注 `fpPosMarks`

`fw` 求交 → 合并相连 / 重叠段（`m.f0 <= last.f1 + 1`）→ 交给 `neckSVG` 的 `o.marks`。
实测：3NPS 把位 1/2/3（1–7 · 3–8 · 5–10）→ 标 **3–8 品**；
3NPS 把位 2 + CAGED E（3–8 · 7–11）→ 标 **7–8 品**。

### 走法 = 三件正交的东西

```js
const FP_DIRSPEC = {
  'up':     { rev:0, shape:'line',   tail:null, code:'u' },
  'ul':     { rev:0, shape:'line',   tail:'hi', code:'l' },
  'down':   { rev:1, shape:'line',   tail:null, code:'d' },
  'dr':     { rev:1, shape:'line',   tail:'lo', code:'r' },
  'updown': { rev:0, shape:'updown', tail:null, code:'b' },
  'du':     { rev:1, shape:'updown', tail:null, code:'n' }
};
```

① **`rev`** 把整条线倒过来（`down` = 上行逻辑的镜像；`du` = 上下行倒过来，语义自动对上）；
② **`shape`** 到顶是否原路折回（`line` 不折 / `updown` 折）；③ **`tail`** 连接尾。

**模进滑窗那一层一行未改** —— 前三档（`up` / `down` / `updown` / `du`）都是 `tail = null`，
既有「几音一组」原样支持。

### ⚠️ 为什么「末音落在某弦某品」不能由滑窗表达

两条**实测**理由：

1. **单元的序 σ 决定末音** —— 末音是 `order[k−1]` 那一格，未必是窗口最后一格。
   3NPS + L2 默认档：线顶点在 5 弦 20 品，走句末音却停在 5 弦 17 品。
2. **L4 套嵌会把单元整体重排**，末音更无法由局部规则预测。

所以收尾降级成「**模进整段走完 → 追加一段独立的连接尾**」。

### ★ 连接尾的定稿口径（第二版）

```js
let tail = null;
if (ln.spec.tail && s2.length){
  const feet = s2[s2.length - 1];
  const kOf = n => n.s + ':' + n.f + ':' + n.midi;
  const j = P.map(kOf).indexOf(kOf(feet));
  const apex = P[P.length - 1];              /* 线的顶点 */
  const on = P.filter(n => n.s === apex.s).sort((a, c) => a.f - c.f);
  const back = (ln.spec.tail === 'hi')
    ? on.filter(n => n.f < apex.f).reverse()   /* 降序 → 收在本弦最低音 */
    : on.filter(n => n.f > apex.f);            /* 升序 → 收在本弦最高音 */
  tail = ((j >= 0) ? P.slice(j + 1) : []).concat(back);
  if (!tail.length) tail = null;
}
```

即：**把线剩下的那段走完（`P.slice(j+1)`）+ 在线的顶点弦折回（`back`）**。

⚠️ **第一版口径（已弃用）** 是「在 body 末音所在的那根弦上折回」。它只保证
「末音 = 本弦极值音」，**保证不了物理极值弦** —— 全枚举只有 **60.3%** 合规
（末音落到别的弦上）。定稿口径：

| 指标 | 第一版 | 定稿 |
| --- | --- | --- |
| 末音落在**物理极值弦** | 60.3% | **3834 / 3834 = 100%** |
| 顶点触达率 | 90.8% | **100%** |
| 尾长 | 0–6 音（均值 1.7） | 0–6 音（均值 1.7） |
| 最大相邻音程 | 19 半音（极端 8/1063） | 20 半音（分布与第一版几乎逐格重合） |

顺带证到：**线的顶点弦 ≡ 物理极值弦 3834/3834** —— 所以「最高音弦」这个说法没有歧义，
**不需要**「直接跳到顶点弦」（那要付最大 19 半音的跳进）。

### 上限截断按**整块**

`fpMoves` 的上限 `PS_MAX_NOTES` 是**按整块截**的（第 67 轮按模进单元截，
会让新档的不变量被切在半句中间）：

```js
const ends = [];  let keep = 0;
ends.forEach(e => { if (e <= PS_MAX_NOTES) keep = e; });
return out.slice(0, keep || ends[0] || out.length);
```

### 专注模式：只留当前那一块（第 82 轮）

工具条上的 `☑ 专注模式`（`#fpFocusChk` ↔ `S.fpFocus`，默认关）。开启后指板图上
**只留正在走的那一块指型的音**，其余打类隐掉；关闭恢复全部音。

**实现只加一层「渲染后打类」**（与视奏页的 `sightPaintSame` 同一手法）：

```js
fpFocusPaint(bi)    // 给 g.note 里不属于第 bi 块的那些打 .blkhide，再标方向条与下沿小字
fpFocusFollow(i)    // 播放推进到走句第 i 项时换到它所属的块
fpMovesBi(bl, seq)  // 走句下标 → 块序 的表；fpRender 里算一次挂在容器上（psHi 每拍要查，不能现算）
```

- `neckSVG` **一个字都不改** —— 探索页 / 分屏 / 视奏页 / 和弦查询连这段代码都碰不到，逐字节零回归。

  与「探索页只看某一块」共用；**幂等** —— 重绘出来的新节点天生干净，所以「关闭开关」就是重绘一次，
  不需要任何反向清理。
- 换块时**只切类、不重画** —— 正在跑的播放定时器、谱面高亮、工具条都不受影响
  （`_audit82.js` 的 Z12：换焦点前后整块 svg 逐字节相同）。

⚠️ **焦点必须在打 `.playing` 之前切。** `psHi` 的顺序是
`psClearHi()` → `fpFocusFollow(i)` → 打 `.ps-hi` → `psHiPosIn()`（打 `.playing`）——
因为 `.note.playing .nc` / `.nl` 有 `opacity:1 !important`，高亮若落在刚被隐掉的音上会把它又亮出来。

**`fpMovesBi` 的认领规则**：`fpMoves` 是按**块**逐块串行铺音的（`bl.list.forEach`），
所以同一块的音在序列里连续。用「各块自己的位置集合」（`fpCellsOf`）贪心认领，
⚠️ **只前进、不回头** —— 相邻把位的窗口共用一些品（共用品就是换把区），
单看一个音的位置可以同时属于两块，回头认领会让焦点在两块之间来回跳。
为此不读 `fpMoves` 没返回的 `ends`、也不给走句项加字段（老输出逐字段不变）。

**焦点是模块级变量 `FP_FOCUS_BI`**，关掉开关**不重置**它 —— 来回切开关时视角不跳。
⚠️ 它导出到 `__T` 的是**启动时的快照**，探针断言一律**读 DOM**
（`#fpDirBar .fp-db.foc` / `#fpFocusCap`），不要读导出值。

**实测（0–24 品 · 标准定弦 · 3NPS · C 伊奥尼亚；`_audit82.js` + 两版截图）**：
共 **7** 块 / **150** 个音位；焦点在第 3 块时 `blkhide` **132** 个、留下 **18** 个
（＝ `bl.of` 里落在第 3 块的位置数，**两边相等**）；关掉开关 `blkhide` 归 0、150 个音全在。
两版对照：旧构建上「专注模式」这一档根本不存在，`S.fpFocus` 没有任何读取点。

## 十四、和弦配置：第二条路 —— 「最常见 / 最易按」（第 72 轮）

### 两种模式是两个**不同的目标**，不是同一算法两档

| | 模式一「声部连接最优」 | 模式二「最常见 / 最易按」 |
|---|---|---|
| 优化对象 | **整条进行** | **每个和弦自己** |
| 算法 | 相邻和弦最优声部配对 + k-best DP（见「五」「六」） | 不做任何跨和弦配对，等价于翻一本和弦表 |
| 方案数 | 最多 3 个（低 / 中 / 高把位区各一个） | 恒 1 个（`常用按法`） |
| 卡上数字 | 「手挪 ∑」＋ DP 综合代价 | 「手挪 ∑」（仅供对照）＋ 各和弦**易按成本** |
| 声部范围 | 吉他 4–5 / 贝斯 3–5 | 吉他 4–6 / 贝斯 3–5（**下限与模式一相同**） |

界面入口 `#vcMode`（`lead` / `easy`），归一化在 `sanitize()` 里：`S.vcMode` 只认这两个值，
脏值一律回落 `lead` —— 所以「玩点即兴」那条路径不受影响。

### 零回归：加的是**可选第三参**

```js
vcCands(it, mid, easy)      // easy 真值 → 走易按打分；不传 → 老口径逐字节不变
vcSolve(items, mid, mode)   // mode === 'easy' → vcSolveEasy；否则原路走 DP
```

反向验证：拿第 4 版构建跑本轮审计 → 18 条 FAIL；拿需求 3 之前的构建跑 → 46 条全 FAIL。

### 易按成本：**必须分档**，纯线性模型不够

第一版是一串线性项（手指 / 横按 / 跨度 / 手位 / 跳弦 / 空弦 / 低音弦 / 闷弦位置）。
拿「教材和弦表」12 个和弦当靶子做网格搜索（7,776 组权重）—— **0 组命中**。
原因都出在「档」上：

1. **没有「第一把位」这一档** → C 被第 5 品的横按 `x35550` 抢走、Dm 被第 10 品抢走；
2. **没有「弦组不许挖空」这一档** → F 被 `1 0 3 x x x`（3 音 2 指）抢走。

再叠加一个自变量：那一版还顺手把易按模式的声部下限放开到 3，于是「声部少 + 手指少」的
薄按法靠两项劣势换一项优势，把教材形状全挤下去了。

**定稿（第 5 版）= 分档 + 声部下限收回。** 档与档的量级拉开，等价于「教材当初挑和弦的那个顺序」：

| 档 | 常量 | 值 | 罚什么 |
|---|---|---|---|
| ① 第一把位优先 | `VE_NOPEN` | 3.00 | 按品超过 4 品后**每高 1 品** |
| ② 弦组不许挖空 | `VE_BADMUTE` | 6.00 | 低音侧之外的**每根闷弦**（等于判死） |
| ③ 手指数 | `VE_FINGER` | 1.15 | 每根手指 |
| ④ 手指不许被顶开 | `VE_SPLIT` | 1.30 | 同一品被「更低的音或空弦」切成两段的次数 |
| ⑤ 空弦奖励 | `VE_OPEN` | 0.30（减项） | 每根空弦 |
| ⑥ 低音弦偏好 | `VE_BASS6` / `VE_BASS5` | 0.85 / 0.55（减项） | CAGED E 型 / A 型 |
| ⑦ 跨度 / 手位 / 跳弦 | `VE_SPAN` / `VE_POS` / `VE_GAP` | 0.42 / 0.06 / 2.80 | 超 4 品跨度每品 / 手位中心每品 / 每跳空 1 根弦 |
| — 低音侧前缀闷弦 | `VE_MUTE` | 0.90 | 按 `前缀长 / (弦数−1)` 加权（`x32010` / `xx0232` 是常规写法，轻罚） |

```js
function vcEasyCostOf(m, n){
  return VE_NOPEN  * Math.max(0, m.fmax - 4)
       + VE_BADMUTE* m.muteBad
       + VE_FINGER * m.fingers
       + VE_SPLIT  * m.splits
       + VE_SPAN   * Math.max(0, (m.fmax - m.fmin) - 4)
       + VE_POS    * ((m.fmin + m.fmax) / 2)
       + VE_GAP    * m.gaps
       + VE_MUTE   * (m.muteLow / Math.max(1, n - 1))
       - VE_OPEN   * m.open
       - (m.bass === 0 ? VE_BASS6 : (m.bass === 1 ? VE_BASS5 : 0));
}
```

**为什么①必须按品罚、不能写成布尔**：写成 `m.fmax > 3`（越位就罚一次）时，
Bm 的第 7 品横按只要「只有一次离位」就赢了。改成按品罚 → 网格搜索从 **0 组命中变成 96 组命中**，
最小余量 0.30。

**为什么要自己数手指（`vcFingerCount`）**：`new Set(fretted).size` 会把横按数成好几根。
物理口径是 —— 同一品的**相邻弦**算一根手指；中间只要隔着「按得更低或闷掉」的弦，
这根手指就压不过去，必须另起一根（累加成 `splits`）。闷弦还分两类：
`muteLow` = 从最低弦起**连续**闷掉的根数（常规写法），`muteBad` = 其余闷弦
（F = `1x3xxx`、G = `32000x` 这类，教材和弦表上根本不写）。

**平局怎么破**：`vcEasyCmp = (b.score - a.score) || (b.notes.length - a.notes.length)` ——
同成本时**声部多的优先**。枚举顺序里同一根弦的「闷」排在各个品之前，少了这一条，
闷掉的那一个会胜出。

## 十五、变调夹与「同一个和弦的多个把位」（第 77 轮）

### 变调夹没有新算法 —— 它是把定弦整体平移

夹在第 N 品 ≡ **琴枕上移 N 品** ≡ 整条定弦的每一根空弦音高 +N 个半音，
而「按下第几品」这个**相对量**一个都不变。于是和弦搜索里唯一要改的是一行：

```js
const midC = cp ? mid.map(m => m + cp) : mid;   /* cp = 变调夹品数 */
```

枚举、打分、成本分档、声部上下限**一行都不用改** —— 它们全都只通过 `midC[s] + f`
看到「这根弦这一品发什么音」。选出来的品与不夹时一一对应，而 `midi` 一律是
**真实发声音高**，所以试听、声部连接、和弦音校验自动跟着对。

**等价性判据（本条最硬）：** 不夹的 **A♯ 型** ≡ 夹 2 品的 **C 和弦**。
即「主音 C + capo 2」选出来的按法，恰好是「主音 A♯ + capo 0」那一套手指位置；
CAGED 页同理，`rootEff = capo ? (((root - capo) % 12) + 12) % 12 : root`，
用 `rootEff` 出落位、品位数字照样相对变调夹写。

### 一个必须记住的不对称：品格上限是**相对量**

```js
const fretsMax = Math.max(win + 1, Math.min(24, S.vcSpan) - cp);
```

「品格上限」说的是**从夹子往上还能按到第几品**，所以夹上之后可用窗口反而变少。
这导致「A♯ 不夹」与「C 夹 2 品」的候选集**只在 `lo ≤ 6` 那一段等价** ——
再往上，不夹那边还有品可弹，夹了这边已经出界。写判据时只能比这一段，
不能拿两个集合整体比。

### 模式二的多把位：同一个目标，换把位各取一次

`vcSolveEasy(items, mid, capo)` 的输出从「恒 1 个方案」变成最多 4 个：

| 方案 | 取法 |
|---|---|
| 常用按法 | 全局最省那一个（`bandObj: null`） |
| 低 / 中 / 高把位区常用按法 | 在该区候选里取该区最省的一个 |

把位区直接共用模式一那套 `VC_BANDS`；`add()` 负责去重 —— 全局最省那一个如果本来
就落在某个区里，那个区就不再出方案（所以实际常见 2–3 个）。每个和弦仍然
**逐和弦独立**，只是把「同一个和弦的几个把位」并排列出来，**不做任何跨和弦配对**。

### `vcCapo` 的存储与兼容

- 落在 `S` 里（`LS = 'gft.v1'`），因此必须在 `sanitize()` 里归一化：
  `S.vcCapo = num(S.vcCapo, 0, 0, 9);` —— 老存档没这个键 → 默认 0 = 不夹，不报错。
- ⚠️ `num()` 定义在 `sanitize()` 那个 IIFE **内部**，事件处理器里调不到。
  下拉的 `onchange` 必须自己夹范围：
  ```js
  const v = parseInt(e.target.value, 10);
  S.vcCapo = (isFinite(v) && v >= 0 && v <= 9) ? v : 0;
  ```
- 三个入口都吃**可选尾参**，不传时逐字节等于第 76 轮：
  `vcCands(it, mid, easy, capo)` / `vcSolveEasy(items, mid, capo)` /
  `vcSolve(items, mid, mode, capo)`；CAGED 侧在 `renderCaged` 内读 `S.vcCapo`，
  但 `capo === 0` 时那条附加文案**整段不输出**，渲染结果与加变调夹之前一致。
- 把位标记画的是**物理** 3 / 5 / 7 / 9 / 12 … 品，换算成相对坐标 `f0 - capo`；
  双重圆点认的是**物理第 12 品**（判据 `f + capo === 12`），不是相对第 12 品。

## 十六、指板练习的谱面视窗（第 79–81 轮）

需求三条 + 一条硬约束：① TAB 每行放 **21–24** 个音；② 谱子进一个**方形视窗**，
视窗尺寸与谱子缩放都可调；③ 练习时谱子自动**跟进**当前音（一边看指板图、一边对照谱子）；
④ **只动「指板练习」页，其它页面一个像素不变**。
第 80 轮又补一条：视窗**长宽各自可调**（不再是正方形），宽度上限提到 **1000**。
第 81 轮是补救②的一个漏洞：**缩小时视窗右边留白** —— 元素宽写成 `100% × z`，缩得越小
内容占得越少。修法是让元素宽恒为 100%，把「变小」改由行宽承担。

### 每行 21–24：给 `psRowSpans` 加一个可选上限

```js
function psRowSpans(n, M){
  if (!(M > 0)) M = PS_MAX_PER_ROW;   /* 不传 = 全局那一档 18 */
  if (n <= M) return [n];
  const k = Math.ceil(n / M), base = Math.floor(n / k), rem = n % k;
  ...
}
```

`PS_MAX_PER_ROW = 18` 仍是全局默认（探索页 / 把位分屏 / 视奏页走的都是它），
只有「指板练习」页在调 `psScoreHTML` 时传 `S.fpRowMax`（21–24，默认 24）。
切法仍是**均分**，所以「上限 24」不等于「每行 24」：102 音是 21/21/20/20/20，
48 音才是 24/24。本页之所以敢放宽，是因为谱子进了视窗、行宽不再受容器宽窄牵制 ——
第 61 轮那条「分页界限与版面 / 乐器 / 定弦无关」的口径**一行未改**。

### 方形视窗：宽度基数是**视窗内宽**，不是绝对像素

第一版把 svg 宽写成 `calc(W × ST_ZOOM px * var(--psvz))`。跑起来才发现不对：
24 个音一行的自然宽是 **1283 px**（viewBox 950 × `ST_ZOOM` 1.35），方形视窗只有 520 px ——
**一进场只看得见三分之一行**，非先点一次「适应宽度」才像话；而视窗尺寸本身可调，
绝对像素在改过尺寸后立刻又不合身。基数于是改成 **100%（视窗内宽）**：

```js
zoomVar
  ? 'width:calc(100% * var(--psvz,1));max-width:none;height:auto;display:block'
  : 'width:' + px + 'px;max-width:100%;height:auto;display:block';
```

于是**缩放 100% = 一行正好铺满视窗宽**，默认视图直接可用；量程随之从 30–200 改成 **50–300**；
「适应宽度」也从 18 行算数退化成一句 `S.fpZoom = 100`。
（同一块谱里各行宽度本就一致 —— 第一遍渲染已把各行统一到最宽行的 `minW` ——
所以按 100% 铺时每行的「每音像素宽」仍然相同，不会一行大一行小。）

### 第 80 轮：把「正方形」拆成长宽两个量

第 79 轮的视窗是 `aspect-ratio:1 / 1` + 一个 `--psv` —— 只能调边长，做不出宽扁或高瘦。
第 80 轮换成显式高度，宽度上限一并从 900 抬到 1000：

| 变量 | 管什么 | 域 | 默认 |
| --- | --- | --- | --- |
| `--psv` | 视窗宽 | 320–1000 px | 520 |
| `--psvh` | 视窗高 | 260–1000 px | 520 |
| `--psvz` | 谱子缩放 | 50–300% | 100% |

```css
.ps-vw .psv-body{width:min(var(--psv,520px),100%); height:var(--psvh,520px); overflow:auto;
  contain:inline-size; padding:8px 10px; box-sizing:border-box; ...}
```

三个实现要点：

- **`height` 用显式值，不用 `aspect-ratio`** —— 后者只能保持比例，做不到「宽高各调各的」。
- **老存档缺 `fpVwH` 时，默认值取归一化后的宽度**，不是硬编码 520：
  `S.fpVwH = Math.round(num(S.fpVwH, S.fpVwSize, 260, 1000))`。
  这样第 79 轮的用户升级上来仍是正方形，观感一字不变（判据 `_audit80.js` 的 F21）。
- **「正方形」按钮与滑块走同一条路径**（只 `setProperty`、不重绘），并顺带把高滑块的
  `value` 与读数一起同步 —— 否则滑块位置与视窗对不上。

高度**不受** `min(…, 100%)` 那种夹取（CSS 里没有 `max-height`），所以「高 1000」在任何窗口宽下都是 1000；
宽度会被所在栏的内宽夹住 —— 那是第 79 轮就定下的「不顶宽整页」行为，第 80 轮只是把上限抬高一档。

`.psv-body` 的宽是 `min(var(--psv), 100%)`。**定宽**的 svg 会顺着「最小内容宽」一路往上传：

| --- | --- |

### 缩放与视窗尺寸走 CSS 变量，不重绘（第 81 轮起缩放除外）

谱子是十来条 SVG。每拖一格都重绘一遍既卡、又会**把滑块自己换掉**（拖动断在半路）——
与位置面板「点一下就弹一下」同源。所以：

- `#fpVwR` → 只 `setProperty('--psv', S.fpVwSize + 'px')`；
- `#fpVwHR` → 只 `setProperty('--psvh', S.fpVwH + 'px')`；
- 「正方形」按钮 → 与 `#fpVwHR` 同一条路径（第 80 轮）；
- `#fpZoomR`（第 81 轮起）→ 铺满态的行宽是算出来的，**必须重排**；但重排只换谱子那一块
  `.ps`（`fpReflowSoon`，90 ms 合并一帧），工具条与滑块不受影响 —— 所以它既不是
  「只改变量」（那会让行宽停在旧值），也不是「整块重绘」（那会打断拖动）；
- 落盘一律**防抖 400 ms**（拖动过程只在松手后写一次 localStorage）；
- 改「每行」会真的改变行数，那一档走整块重绘；「视窗 / 通栏」同理。

### 谱子跟进：两个纯函数，两轴分工

```js
function fpFollowDelta(r){   /* 纵向：按「行」判，落点是行首 */
  if (r.elTop >= r.bodyTop && r.elBot <= r.bodyBot) return 0;
  return Math.round(r.rowTop - r.bodyTop) - 4;
}
function fpFollowDX(r){      /* 横向：按「当前音」判，落点是视窗正中 */
  if (!(r.bodyW > 8)) return 0;
  const m = 20;
  if (r.elLeft >= r.bodyLeft + m && r.elRight <= r.bodyRight - m) return 0;
  return Math.round((r.elLeft + r.elRight) / 2 - (r.bodyLeft + r.bodyRight) / 2);
}
```

- 判据都是「当前音在不在窗内」，**落点**不同：纵向落**行首**（一行一行地翻，眼睛不追半行），
  横向落**视窗正中**（挪一次够几拍用，所以视窗不会每一拍都晃）。
- 横向**必须**做：缩放 200% 时一行显示宽是视窗的两倍。只做纵向的话，按纵向判「看得见」
  会报 true，而高亮其实飘在视窗右侧外面 —— 第一版正是这么漏掉的。
- 副作用只在 `fpFollowTo(el)` 里发生，且**只在 `.psv-body` 里滚**：
  探索页 / 把位分屏 / 视奏页没有这个容器，`closest` 返回 `null` → 整段直接返回，
  那几页一个像素都不动。

### 第 81 轮：缩小时把行宽顶上去（右边不留白）

第 79/80 轮的宽度写法是 `width:calc(100% * var(--psvz,1))` —— 缩放 70% 时**元素自己**
只有视窗内宽的 70%，右边那 30% 是元素之外的空白，谱子再怎么排也填不进去
（浏览器实测 `fillRat` 0.933 → 0.656）。根子在于 **svg 的 `viewBox` 恒等于内容宽**：
「让内容变小」只能改内容本身，改元素宽度没用。第 81 轮把两件事拆开：

| | 元素宽（`psWidthStyle`） | 行宽（`stStaffSVG` 的 `stretch`） | `--psvz` |
| --- | --- | --- | --- |
| 铺满态（≤ 100%） | `calc(100% * var(--psvz))`，而 `--psvz` 恒为 1 | σ 倍步进，把最宽行顶到 `rowW / z` | 恒 `1` |
| 放大态（> 100%） | 同上，`--psvz` = z | σ = 1（自然宽，不压缩） | `z` |

- **σ 的精确解**：`W(σ) = W(1) + n·step·(σ−1)` —— 随 σ 变的只有每音的横向步进
  （前缀 / 调号 / 拍号 / 小节线 / 记号都不随它变），于是
  `σ = 1 + rowW·(1/z − 1)/(n·step)`，其中 `rowW` 是第一遍量出的最宽行宽、`n` 是那一行的音数、
  `step = stStepOf(dur)`；余数只来自 `ceil`（≤ 1 个单位）。`minW`（各行统一的画布宽）
  同步换成 `ceil(rowW / z)`，否则各行被压的倍率不一致、符头会一行大一行小。
- **σ ≥ 1 恒成立**（只在 z < 1 时算），所以是「把音符排开」而不是「压缩」——
  压缩会把两位数的品号叠在一起。放大态干脆不压缩：放大是「看得更大」，
  一行比视窗宽就横滚，本来就该如此（`fpFollowDX` 负责把当前音带回来）。
- **行数与每行音数不随缩放变**：铺满只改行宽、不重排行。于是「每行 21–24」这一档在任何缩放档
  都成立，「每行」与「缩放」各管一件事，不会互相打架。代价是一首曲子的总行数不变
  （不像「缩小时多塞几个音」那样会变少）—— 这是有意选的：缩放该像缩放，
  而不是偷偷改掉用户设的每行音数。
- **`stStepOf(d)` 从 `stStaffSVG` 里提到了模块级**：算 σ 与真正乘步进必须是同一个式子，
  两处各写一份迟早会走散。不传 `stretch` 时它恒为 1，其它页面的渲染逐字节不变。

**重排只换谱子那一块。** 缩放现在影响排版，所以拖滑块必须重排；但整块重绘 `#fpBoard`
会把正在拖的滑块一起换掉（拖动断在半路）。`fpReflow()` 因此只换那一块 `.ps`
（`el.outerHTML = psScoreHTML(...)`，输入取自 `fpRender` 留在 `box.__fpSc` 上那一份），
工具条与滑块仍是原来的节点；拖动期间 90 ms 合并一帧，且每次都读当时的 `S.fpZoom`，
所以丢帧只会慢半拍、不会停在旧档位。

浏览器级实测（`_shots81.ps1`：宽 1000 × 高 420 的视窗、DPR 1.5、连拍两遍同哈希）：

| 场景 | 旧 `fillRat` | 新 `fillRat` | `glyphH`（旧 / 新） | `gap`（旧 / 新） |
| --- | --- | --- | --- | --- |
| 缩放 100% | 0.933 | 0.933 | 14 / 14 | 40.8 / 40.8 |
| 缩放 70% | **0.656** | **0.935** | 10 / 10 | 28.6 / **42.5** |
| 缩放 50% | **0.472** | **0.938** | 7.3 / 7.3 | 20.4 / **43.7** |

`fillRat` = (第 1 行最后一个音的右沿 − 视窗左沿) / 视窗宽。两个量必须一起看：
只看 `fillRat` 会漏掉「干脆不缩放了」，只看 `glyphH` 会漏掉留白 —— 所以判据是
「`fillRat` 与 100% 时同值」**且**「`glyphH` 确实按比例变小」。100% 档两版九项数值全同
（连图片字节数都相同），说明默认视图一个像素没动。
